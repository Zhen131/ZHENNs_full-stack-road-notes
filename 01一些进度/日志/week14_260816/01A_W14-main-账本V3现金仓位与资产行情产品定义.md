## 结论

本批先把账本升级为能够承载真实数据的 V3：增加一个统一的 USDT 现金仓位，并把“本地资产”与“Binance 行情映射”拆成两个独立概念。资产不再受 BTC、ETH、ADA 三项初始清单限制；没有 Binance 交易对时，资产仍可记账并使用手动价格。

这份 `01A` 只固定产品决定，不是执行文档、测试合同或代码修改授权。后续关系为：`01A → 提示词 0 → 全新目标模式生成 01B → 另行确认后执行`。`01B` 负责落实技术方案、边界和测试，不得静默改写本文件的产品决定；若发现冲突，必须退回产品层确认。

## 一、当前问题的确认

- 当前架构并非只能处理三种 Binance 交易对；行情验证与刷新能力可消费账本中的任意资产映射。
- 真正限制来自产品入口：初始资产和兼容回退只预置 BTC、ETH、ADA，行情页面只能编辑已有资产，却没有新增本地资产的入口。
- 当前账本没有独立现金事实与现金余额，因此买卖无法形成完整的 USDT 流转，真实周报中的现金仓位也无法表达。

## 二、USDT 现金仓位

| 项目 | 已确认规则 |
| --- | --- |
| 现金定义 | 全账本只有一个汇总 USDT 现金池；周报里的 `$` 现金统一按等值 USDT 处理，不引入 USD、USDC、人民币或分交易所账户。 |
| 记账入口 | 继续使用现有记账页。在资产选择中增加“现金 USDT”这一特殊入口；选择普通资产时显示买卖表单，选择现金时切换为现金表单。USDT 在界面上统一出现，但数据上不伪装成普通加密资产。 |
| 自动流转 | 买入普通资产自动扣减 USDT，卖出普通资产自动增加 USDT；用户不得再为同一笔交易手工补记一条反向现金记录。 |
| 现金事件 | 支持入金、出金、外部支出和余额校准。校准时用户输入交易所实际 USDT 余额，账本计算差额并保存一条可见校准事实，不删除或篡改旧记录。 |
| 负余额 | 允许保存负现金，以容纳早期记录缺失；保存前必须明确显示缺口并二次确认，不能把缺口静默修成零。 |
| 展示范围 | 现金计入总资产、资产分配、持仓明细和资产趋势；不计算平均购价、未实现盈亏，也不进入交易热力图。交易页按时间统一展示买卖与现金事件，并可按记录类型或 USDT 筛选。 |
| 导入边界 | B 文件中的现金事实必须在写入 C 前完成预检。发现结构错误或互相矛盾时阻止导入并给出可复制的中文报告；程序不自动修复，报告交回 B 文件生成者处理。 |

本批不新增“累计净投入”或“整体资金收益率”口径；这些指标尚未完成产品讨论，`01B` 不得自行推导。早期缺失的币种买卖记录也不在本批伪造，后续真实数据整理另行决定。

## 三、本地资产与 Binance 行情

必须分开维护三层对象：本地资产决定能否记账；可选 Binance 映射只负责联网价格；历史交易和手动价格属于账本事实，不因映射变化而删除。

| 场景 | 已确认行为 |
| --- | --- |
| 离线新增资产 | 设置页增加“资产与行情”。用户只输入资产代码即可创建本地资产，整个过程不联网；SOL、DOGE、BNB、OKB、KNIGHT 等都不需要写入固定白名单。 |
| 联网添加映射 | 用户明确发起搜索时，可输入 `SOL` 或 `SOLUSDT`；程序只验证 Binance Spot 的 USDT 交易对。暂不支持中文名或完整英文名搜索。 |
| 行情刷新 | 映射保存成功后允许取得一次价格；以后仍由用户主动点击刷新，不加入轮询、WebSocket 或后台自动联网。 |
| 无交易对 | Binance 不存在该交易对或当前离线时，本地资产继续可记账、可导入、可录入手动价格，失败不得删除资产。 |
| 删除映射 | 随时允许删除；资产、交易、价格与手续费规则继续保留，记账下拉框也继续显示该资产。 |
| 删除资产 | 只有该资产完全没有交易、价格和手续费规则等依赖事实时才允许彻底删除；否则明确拒绝。本批不增加“归档／停用资产”功能。 |
| B 文件导入 | B 中的资产自动进入本地资产清单和记账入口；导入过程绝不联网。导入成功后只报告缺失映射，并提供用户主动点击的“联网自动配对”；配对失败不回滚已经导入的账本。 |
| B／C 持久化 | 本地资产及其可选映射都属于账本配置，随 B 导出并保存在 C 中；删除映射只改变配置，不改变历史事实。 |

## 四、V3 与真实数据通过线

- 本批采用干净升级：`LedgerData schema 3`，明文导入导出文件升级为 `BackupEnvelope V3`。
