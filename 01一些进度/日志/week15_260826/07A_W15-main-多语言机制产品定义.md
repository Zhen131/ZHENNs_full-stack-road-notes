## 结论

本批只做一件事：**把「界面文字可以换语言」这套机制搭起来，并只用一个页面做示范。**

**本批不搬文案。** 约 1,260 行界面文案的搬运是 09 批的事。本批的价值是**把所有未知消掉**——方案是否适配本仓库架构、821 处中文测试断言怎么办、结构守卫怎么改。方案错了，只浪费一个页面。

支持三种语言：**中文（默认）、英文、匈牙利语**。

真实账户金额与持仓数量一律不写入本文件及任何开发日志，全文只使用虚构数据。

## 一、第零步：先修 14 处排序确定性（必须最先）

### 1.1 为什么排在最前

`localeCompare` 不传第二个参数时，按**运行环境的默认语言**比较字符串。同一份账本在不同语言的系统上，排序结果理论上可能不同。

三个理由决定它排在本批第一步：

1. **它与语言直接相关**，与本批同一主题；
2. **必须在 09 批之前完成**——09 会产出波及百余文件的巨型 diff，之后再动这些代码不好审；
3. **不适合放 08**：08 的硬边界是「不得改变任何外部行为」，而修排序理论上会改变顺序，性质冲突。

### 1.2 清单与分档

截至 `main@8df62d8` 实测共 14 处未指定语言（另 3 处已显式写 `"en"`）：

| 档 | 位置 | 处理 |
| --- | --- | --- |
| **必修** | `core/calculations/cashReplay.ts:102`、`core/shared/ledgerDate.ts:83`、`features/activity/activityService.ts:81` | **在派生计算路径上**，`cashReplay` 直接参与现金余额计算，必须确定性 |
| 一并修 | `app/TransactionsWorkspace.tsx:544`、`features/market-data/binanceMappingService.ts:95`／`:106`、`features/trades/TradeForm.tsx:351`、`features/charts/chartDataService.ts:196`／`:445`／`:618`、`features/portfolio/HoldingsOverview.tsx:22`、`features/portfolio/ledgerProjection.ts:398`、`features/backup/backupDuplicateGrouping.ts:291` | 只影响显示顺序，但一并统一更干净 |

### 1.3 改法与通过线

比较对象均为 ISO 日期串、资产代号、技术 id 等纯 ASCII，**首选直接用 `<` / `>` 比较**（确定性由定义保证，且更快）；若某处确需按人类习惯排序，显式传 `"en"`。

| 编号 | 硬要求 |
| --- | --- |
| L-1 | **必须跑 04 批冻结的派生等价性快照（7/7），确认排序结果一字未变。** 这是本步唯一的裁判 |
| L-2 | 本步独立成一笔或数笔提交，**不与后续多语言改动混在同一笔** |
| L-3 | 若发现某处改后快照不符，**停止并申报**，不得自行调整快照 |

**诚实标注**：比较对象是纯 ASCII，实际出错概率很低，**未实测其会出错**。修它的理由是「现状是碰巧没事而非设计上不会有事」，且同一文件内已有 3 处显式写了 `"en"`，说明当初想到了却没想全。

## 二、产品决定：自研，不引入 i18n 库

### 2.1 判据

引入现成库的主要价值是它替你处理三件难事。**其中两件已被先前的产品决定主动规避：**

| 库擅长的 | 本产品的情况 |
| --- | --- |
| 数字本地化 | **已规避。** 数字统一用空格作千分位、点作小数点，不随语言变（见 2.4） |
| 日期本地化 | **已规避。** 日期统一 ISO 格式 `YYYY-MM-DD`，全世界一致 |
| 语法复数 | **本批用 2.3 的措辞规则规避** |

三件难事全部不适用，**为此引入一个需要长期维护与安全审查的依赖不划算**。自研规模约为「一张表 + 一个 Context + 一个 `t()`」，数十行量级。

### 2.2 架构决定：引入本项目第一个 React Context

**2026-08-31 查明：本仓库当前没有任何 React Context**（全仓 `createContext` 零命中），状态一律靠 props 逐层传递。

本批引入 Context 提供 `t()`，**这将是本项目第一个 Context**。该决定须明确论证而非默认发生：

| | 说明 |
| --- | --- |
| 为什么必须 | 09 批将有百余个文件需要 `t()`，逐层传 props 不可行 |
| 为什么合适 | 多语言正是 Context 的教科书用例：**值被很深很广地需要、且极少变化** |
| 为什么不扩散 | 本批**只允许新增这一个 Context**。任何其他状态一律沿用现有的 props 传递，不得借机改造 |

替代方案（模块级单例 + 顶层强制重渲染）已考虑并否决：它绕过 React 的数据流，语言切换后何时重渲染变得不可预测。

### 2.3 措辞规则：用改写规避语法复数（硬要求）

**禁止任何依赖语法数的文案。** 不写「9,000 apples」「1 item」这类把数字嵌进句子、并要求名词随数字变形的表达。

统一改为**标签 + 数值**的形式：

| 禁止 | 采用 |
| --- | --- |
| `9,000 transactions` | `Transactions: 9 000` |
| `1 asset` | `Assets: 1` |
| `共 103 条，第 1 / 2 页` | 保持「标签＋数值」的结构，翻译时三种语言各自给出不含语法数变化的表述 |

理由：语法复数只在少数语言中存在，中文没有；为一个语言的语法特性引入整套复数规则机制不划算。**标签＋数值的写法在三种语言中都成立，且排版更整齐。**

**该规则是硬要求，`09` 批搬运文案时同样适用。** 若发现某条既有文案无法在不引入语法数的前提下翻译，**停止并申报**，由产品负责人裁决改写方案，不得自行引入复数机制。

### 2.4 数字与日期表示法：不本地化

| 项 | 决定 |
| --- | --- |
| 数字 | **全部语言统一 `1 234 567.89`**：空格作千分位，点作小数点。ISO 31-0／SI 推荐此写法，正是为避开逗号与句点在各国含义相反的问题 |
| 日期 | **全部语言统一 ISO `YYYY-MM-DD`** |

理由：同一串 `1,234` 在英文里是一千二百三十四、在匈牙利语里是一点二三四，**相差一千倍**。在记钱的软件里这是能导致真实损失的歧义。

**顺带更正一处常见误解**：中文金融与会计场合的标准同样是三位一撇，四位一组（万、亿）属口语与摘要场景，不用于账本表格。因此本决定只需调和「中英一套」与「匈牙利一套」，统一为第三套后反而最省事。

`src/ui/formatLedgerNumber.ts` 当前为手写实现（`.` 小数点、`,` 千分位，不依赖系统语言），本批改为空格千分位，**仍不依赖系统语言**。

## 三、放置与边界

### 3.1 文案表与 `t()` 放 `src/ui/`

| 判据 | 说明 |
| --- | --- |
| 同类 | `src/ui/` 已承载 `formatLedgerNumber.ts` 等纯展示逻辑，文案表是同一类东西 |
| 可达 | `@/ui` 是结构守卫认可的稳定入口，`app` 与 `features` 均可引用 |
| 不新增源码区 | 守卫的六区（`app`／`core`／`features`／`platform`／`test-support`／`ui`）不变 |

### 3.2 `core` 与 `platform` 不得引入 `t()`

**纯计算层与平台层不生成用户可见文案。** 它们只吐错误码，由界面层翻译。

`src/core` 当前有 11 处中文在字符串里（如 `core/policies/ledgerFactPolicy.ts:127`），**属既有欠账，本批不处理**，登记给 09 批。**但本批不得让情况变得更糟**：不得在 `core`／`platform` 中新增任何用户可见文案，也不得让这两层引用 `@/ui`。

### 3.3 语言偏好的存放位置

| 编号 | 硬要求 |
| --- | --- |
| P-1 | **绝对不得存进账本文件。** 界面语言是「这台电脑的偏好」，不是「账本的数据」。存进去会迫使 `ledgerSchemaVersion` 为一个 UI 设置而升版，**并当场使 2026-08-28 那份 B 文件失效**——那是用户当前唯一的退路 |
| P-2 | 存放介质由 `07B` 在实现时选定并说明，须能在刷新后保持；**不得写入任何与账本数据同生命周期的存储** |
| P-3 | 读取失败或值非法时，**静默回落到中文默认**，不得阻塞应用启动 |

## 八、本批产出对论文的作用

多语言不在论文范围内，因此**本批不作为论文贡献点**。但两项副产物可用：

1. **一条设计判断**：有意识地选择不本地化数字与日期，理由是金融软件中本地化的小数点是误读风险（同一串 `1,234` 在两种语言中相差一千倍）。这属于 design rationale，比无意识地做了更能体现判断力。
2. **一条诚实边界**：论文中不得把多语言写成论文范围内的工作，也不得暗示它是原方案的一部分。
