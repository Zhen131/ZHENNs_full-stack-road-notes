# 02A_W15-main｜首页持仓表用词统一与成本列校正产品定义

- 日期：2026-08-28
- 轨道：长期账本产品 `main`
- 状态：产品定义已确认；执行合同见 `02B`
- 前置：本批建立在 `01A`／`01B` 已合入 `main@10c243f` 的结果之上

## 结论

首页“持仓成本”表把两套不同含义的成本并排放在同一行，并使用了会诱导用户做减法的字段名，构成影响用户信任的高优先级显示缺陷。

**底层计算没有错误。** 持仓重放、剩余成本、已实现盈亏、未实现盈亏四者互相自洽，本批一个公式都不改、一位精度都不动。

本批只做三件事：

1. **换列**：把首页持仓表里的“总花费”整列换成“剩余持仓成本”。
2. **统一用词**：同一个底层数字在首页三个位置必须使用同一个名字。
3. **移列**：“累计买入流出”不删除，移到「完整持仓详情」面板，并明确标注它不参与同表其他列的相减。

这份 `02A` 只固定产品决定，不是执行文档，也不是代码修改授权。执行合同见 `02B`，执行结果见 `02C`，独立验收见 `02D`。

真实账户金额与持仓数量一律不写入本文件及任何开发日志，全文只使用虚构示例。

## 一、问题确认

### 1.1 现象

首页“持仓成本”表当前有八列：

> 币种、当前价格、平均购价、涨跌幅、盈亏金额、持仓量、总花费、当前市值

用户看到“总花费”和“盈亏金额”并排，会自然理解为：

```
盈亏金额 = 当前市值 − 总花费
```

程序实际算的是：

```
未实现盈亏 = 当前市值 − 剩余持仓成本
```

而“总花费”实际是**历史累计买入现金流出**。两者不是一组可以相减的数字。

### 1.2 底层有两套成本，各自都对

| 字段 | 代码位置 | 含义 | 会被什么改变 |
| --- | --- | --- | --- |
| `Position.costBasis` | `positionReplay.ts` | 现在还持有的这些币，当初一共花了多少 | 卖出按比例扣减；外部转出整块扣减；链上手续费按比例扣减；外部转入与白拿按到账单价增加 |
| `buyOutflowByAsset` | `pnlSummaryService.ts` | 历史上所有买入一共掏出去多少现金 | 只增不减；外部转入与白拿完全不计入 |

两者的差额里混着三种互相独立的成分：已卖出部分的成本、已转出部分的成本、非买入获得而计入的成本。**没有任何单一系数可以把其中一个换算成另一个。**

### 1.3 现有八列中有七列是自洽的

| 列 | 来源 | 关系 |
| --- | --- | --- |
| 持仓量 | `Position.quantity` | — |
| 平均购价 | `Position.averageCost` = `costBasis ÷ quantity` | 与剩余成本同源 |
| 当前价格 | `Position.latestPrice` | — |
| 当前市值 | `Position.marketValue` = `quantity × latestPrice` | — |
| 盈亏金额 | `Position.unrealizedPnl` = `marketValue − costBasis` | 与剩余成本同源 |
| 涨跌幅 | `(latestPrice − averageCost) ÷ averageCost` | 与剩余成本同源 |
| 总花费 | `buyOutflowByAsset` | **唯一的外来户** |

七列同源，一列外来，且外来的那一列名字最像“可以拿来减”的那个。这是缺陷的全部成因。

### 1.4 同一个页面已经存在三套叫法

| 位置 | 剩余成本叫 | 浮盈浮亏叫 | 均价叫 | 已落定盈亏叫 |
| --- | --- | --- | --- | --- |
| 首页顶部四张指标卡 | 剩余持仓成本 | 未实现盈亏 | — | 已实现盈亏 |
| 首页持仓表（本批目标） | 不显示，显示“总花费” | 盈亏金额 | 平均购价 | — |
| 完整持仓详情面板 | 剩余含费成本 | 未实现净盈亏 | 含费平均成本 | 已实现净盈亏 |

顶部卡片已经用对了名字，下方表格却用了另一套，中间没有任何提示。**这一条是本批优先级最高的部分：即使不换列，用词也必须统一。**

### 1.5 “涨跌幅”本身也误导

`涨跌幅 = (当前价格 − 平均购价) ÷ 平均购价`，衡量的是当前价格相对**自己的持仓成本**的偏离，不是价格在时间上的涨跌。用户看到“涨跌幅 −8.7%”会理解成“今天跌了 8.7%”，这是第二处词不达意，本批一并修正。

### 1.6 空投类资产会让错误反向发生

当一个币种存在外部转入或白拿时，剩余持仓成本可能**大于**累计买入流出。此时现有界面会让用户算出一个虚假的盈利。这类资产在 V4 之后会正常出现，不是异常数据。

## 二、根因判断

不是算错，是**一行里混了两套成本，并且用了让人一定会相减的名字**。修法只在显示层，不涉及任何计算、精度或历史事实。

## 三、产品决定

### 3.1 统一词表（本批的核心）

以下叫法在全部界面、提示文案、无障碍名称中唯一有效，不得再出现同义异名：

| 底层字段 | 统一叫法 | 一句话解释 |
| --- | --- | --- |
| `Position.quantity` | 持仓量 | 现在还拿着多少个 |
| `Position.latestPrice` | 当前价格 | — |
| `Position.marketValue` | 当前市值 | 持仓量 × 当前价格 |
| `Position.averageCost` | **持仓均价** | 现在手上这些币，平均每个花了多少 |
| `Position.costBasis` | **剩余持仓成本** | 现在手上这些币，一共花了多少 |
| `Position.unrealizedPnl` | **未实现盈亏** | 当前市值 − 剩余持仓成本 |
| `Position.realizedPnl` | **已实现盈亏** | 卖出、外部转出、链上手续费已经落定的盈亏 |
| `buyOutflowByAsset` / `buyOutflow` | **累计买入流出** | 历史上买入一共掏出去多少现金 |
| `(latestPrice − averageCost) ÷ averageCost` | **相对均价涨跌** | 当前价格比自己的持仓均价高多少或低多少 |

被废弃、界面上不得再出现的旧叫法：

> 总花费、盈亏金额、平均购价、涨跌幅（用于上述比值时）、含费平均成本、剩余含费成本、已实现净盈亏、未实现净盈亏、累计买入总支出

“含手续费”这一事实不因为词表简化而丢失：持仓均价与剩余持仓成本均已包含手续费，该事实改为写在表格说明文字中，而不是塞进每一个列名。

### 3.2 首页持仓表的新结构

卡片标题由「持仓成本」改为「**当前持仓**」。

说明文字改为：

> 按当前市值展示前五。本表所有数字都只描述现在还持有的部分；持仓均价与剩余持仓成本均已包含手续费。

八列（列数不变，最小宽度不变，首页布局行结构不变）：

| 币种 | 当前价格 | 持仓均价 | 相对均价涨跌 | 未实现盈亏 | 持仓量 | **剩余持仓成本** | 当前市值 |
| --- | --- | --- | --- | --- | --- | --- | --- |

唯一的数据变化：第七列的数据来源由 `buyOutflowByAsset` 改为 `Position.costBasis`。

现金 USDT 行保持现状，单独一行，不参与相对均价涨跌与着色。

### 3.3 换列之后这一行必须能自校验

改完之后，同一行内任取两个数相减都成立：

| 等式 | 说明 |
| --- | --- |
| 当前市值 − 剩余持仓成本 = 未实现盈亏 | 用户最可能做的那个减法，现在是对的 |
| 持仓量 × 持仓均价 = 剩余持仓成本 | — |
| (当前价格 − 持仓均价) ÷ 持仓均价 = 相对均价涨跌 | — |
| 剩余持仓成本 × 相对均价涨跌 = 未实现盈亏 | 交叉验算 |

**这条是本批的产品目标本身：一个普通用户拿计算器按任意两列，都不会得到与界面矛盾的结果。**

### 3.4 累计买入流出的去向

“累计买入流出”是 `01` 批刚建立的能力，不删除，改放位置：

| 项目 | 决定 |
| --- | --- |
| 首页持仓表 | 移除该列 |
| 完整持仓详情面板 | 新增一列「累计买入流出」，排在最右侧，与其余列之间用视觉分隔 |
| 面板说明文字 | 必须写明：该列是历史累计现金支出，不与本表其他任何列相减 |
| 计算逻辑 | `pnlSummaryService.ts` 的 `buyOutflowByAsset` 一字不改，只改它被传给谁 |
| 缺失原因提示 | 既有的“不可完整计算”与原因串保持不变 |

### 3.5 本批不新增的东西

| 候选 | 决定 | 理由 |
| --- | --- | --- |
| 持仓表新增「已实现盈亏」列 | **不加** | 顶部卡片已有全账本总数，详情面板已有按币种拆分。持仓表定位是“现在的仓位”，塞进历史数字等于重犯本批要修的错 |
| 新增「累计净盈亏」 | **本批不加** | 公式与边界见第四节，需要新增按币种的累计卖出流入，属于新计算能力，另行立项 |
| 新增「白拿计入价值」展示 | **本批不加** | `giftIncome` 已在底层累计，展示位置与说法另议 |
| 首页布局调整 | **不动** | 列数不变，`01A` 第十六节确定的四行结构原样保留 |

## 四、累计净盈亏的严格公式与边界（本批不实现，仅固定结论）

严格定义只有一个：

```
累计净盈亏 = 已实现盈亏 + 未实现盈亏
```

它满足一个精确恒等式：

```
累计净盈亏 = 当前市值 + 累计卖出流入 − 累计买入流出
             − 外部转入计入的成本 − 白拿计入的成本
```

三条必须同时说明的边界：

1. 只有**从不存在外部转入、也从不存在白拿**的账本，才等于「当前市值 + 累计卖出流入 − 累计买入流出」。V4 之后这个前提通常不成立。
2. 白拿按到账单价计入成本，因此白拿在到账那一刻盈亏为零，白得的价值**永远不进入累计净盈亏**。这是 `01A` 第三节确定的产品规则，不是缺陷。
3. 外部转出把整块成本记为已实现亏损。若用户把币提到账本外但实际仍持有，该“亏损”是记账方式造成的，累计净盈亏会因此偏低。

实现前提：`pnlSummaryService.ts` 目前只有全账本一个 `sellProceeds`，**没有按币种拆分**。要按币种展示累计净盈亏，必须先新增按币种的累计卖出流入。这属于新计算能力，不在本批。

---

## 五、哪些数字可以相减，哪些不能（固定结论）

**可以相减：**

- 当前市值 − 剩余持仓成本 = 未实现盈亏
- 持仓量 × 持仓均价 = 剩余持仓成本
- 已实现盈亏 + 未实现盈亏 = 累计净盈亏

**不可以相减：**

- 当前市值 − 累计买入流出（现有界面正在诱导用户做的那个减法）
- 累计买入流出 − 剩余持仓成本（差额里混着已卖出成本、已转出成本、非买入计入的成本三种成分）
- 持仓均价 × 任何历史时点的数量（均价是当前值，历史每一刻都不同）

## 六、虚构示例（全部为编造数字，非真实账本）

三个例子分别覆盖卖出、外部转出、白拿三种让两套成本分家的原因。

### 6.1 BTC：卖出

| 步骤 | 结果 |
| --- | --- |
| 买入 0.10 枚 @ 30,000 | 花掉 3,000 |
| 买入 0.05 枚 @ 40,000 | 花掉 2,000 |
| 小计 | 累计买入流出 5,000；持仓 0.15；剩余持仓成本 5,000；持仓均价 33,333.33 |
| 卖出 0.05 枚 @ 50,000 | 收回 2,500；卖出部分成本 0.05 × 33,333.33 = 1,666.67；**已实现盈亏 +833.33** |
| 卖出后 | 持仓 0.10；**剩余持仓成本 3,333.33**；**累计买入流出仍为 5,000** |
| 今日价格 45,000 | 当前市值 4,500；**未实现盈亏 +1,166.67** |

- 旧界面诱导的算法：4,500 − 5,000 = **亏 500**
- 新界面：4,500 − 3,333.33 = **+1,166.67**，与显示的未实现盈亏完全一致
- 事实：已落袋 +833.33，账面浮盈 +1,166.67，合计 +2,000。差额 2,500 是卖出收回的现金，不在市值里

### 6.2 ETH：外部转出

| 步骤 | 结果 |
| --- | --- |
| 买入 2 枚 @ 2,000 | 花掉 4,000；剩余持仓成本 4,000 |
| 外部转出 1 枚 | 剩余持仓成本减 2,000；**已实现盈亏 −2,000** |
| 转出后 | 持仓 1 枚；**剩余持仓成本 2,000**；**累计买入流出仍为 4,000** |
| 今日价格 2,400 | 当前市值 2,400；**未实现盈亏 +400** |

- 旧界面诱导的算法：2,400 − 4,000 = **亏 1,600**
- 新界面：2,400 − 2,000 = **+400**
- 事实：手上这 1 枚是浮盈的；那笔 −2,000 是“币离开了账本”，与这 1 枚的盈亏无关

### 6.3 SOL：白拿

| 步骤 | 结果 |
| --- | --- |
| 白拿 10 枚，到账单价 20 | 剩余持仓成本 +200；**累计买入流出 +0** |
| 买入 5 枚 @ 24 | 花掉 120 |
| 小计 | 持仓 15；**剩余持仓成本 320**；持仓均价 21.33；**累计买入流出 120** |
| 今日价格 18 | 当前市值 270；**未实现盈亏 −50** |

- 旧界面诱导的算法：270 − 120 = **赚 150**
- 新界面：270 − 320 = **−50**
- 事实：这是浮亏。注意此例中剩余持仓成本（320）**大于**累计买入流出（120），旧界面的错误方向与前两例相反
