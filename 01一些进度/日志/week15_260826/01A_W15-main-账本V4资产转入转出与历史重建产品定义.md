## 一、问题确认

账本数量与真实数量不一致，来源是三条互相独立的缺口：

| 编号 | 缺口 | 性质 |
| --- | --- | --- |
| G-1 | 账本只能表达“买卖”与“现金进出”，无法表达充币、提币、空投、理财利息、平台赠送 | schema 能力缺失，非计算错误 |
| G-2 | 历史转换的中段窗口使用自然语言笔记范围，而非交易所全量成交 | 数据源不完整 |
| G-3 | 永续合约盈亏与资金费只登记了两个窗口，其余月份未入账 | 转换决定不完整 |

G-1 已由既有转换决定记录自行证明：其 `decisions.json` 明确写有“V3 无资产转入类型”，并因此采用变通手段维持可重放性。G-1 是本批的主因，G-2 与 G-3 在重新生成 B 文件时一并修正。

判定 G-1 为主因的证据：由交易所账单还原的“买卖净增”与账本显示的持仓数量在受影响币种上完全一致，说明重放算法正确，差额全部来自无法表达的非买卖获得。

## 二、资产转入转出事实

新增一类账本事实，覆盖一切非买卖引起的持仓数量变化。

| 字段 | 规则 |
| --- | --- |
| 时间 | 与既有事实一致，支持日、分、秒三种精度；不得晚于今天 |
| 币种 | 必须是账本中已存在的本地资产 |
| 数量 | 高精度十进制，必须为正；方向由独立字段表达 |
| 方向 | 进入 / 离开 |
| 原因 | 充币、提币、空投、利息、平台赠送、内部转移 |
| 当日单价 | 仅“白拿类”必填，用于计入成本；“搬家类”不得填写 |
| 存放位置 | 来源与去向，取值见第四节 |
| 备注 | 可选，上限与既有事实一致 |

### 两种成本口径

| 类别 | 包含原因 | 数量 | 成本 | 盈亏 | 现金 |
| --- | --- | --- | --- | --- | --- |
| 搬家类 | 充币、提币、内部转移 | 不变 | 不变 | 不产生 | 不变 |
| 白拿类 | 空投、利息、平台赠送 | 增加 | 按到账当日单价计入 | 记为等额收益 | 不变 |

搬家类只改变存放位置，账本总持仓与平均购价不受影响。白拿类必须按到账当日单价计入成本，不得按零成本计入：零成本会在用户未支出任何资金的情况下压低平均购价，使平均购价失去指导买卖的作用。

平台赠送单独归类，不计入个人本金口径。

### 拒绝规则

- 离开数量大于当前该币种持仓时拒绝保存，比照既有卖出超量规则
- 白拿类缺少当日单价时拒绝保存
- 搬家类填写单价时拒绝保存
- 未来日期的转入转出比照既有未来事实规则隔离

## 三、永续合约

本批不为账本增加合约交易能力。历史合约盈亏与资金费按月汇总，折为既有现金事实写入，备注注明来源为合约。现金时间线因此可对齐，现货持仓与平均购价不受污染。

后续若需要合约建模，另行立项，不在本批范围。

## 四、存放位置

持仓引入存放位置维度，取值为交易所、冷钱包、冷钱包理财。

| 项目 | 规则 |
| --- | --- |
| 计入范围 | 三个位置的持仓全部计入总资产、平均购价与未实现盈亏 |
| 展示 | 持仓明细增加存放位置列；首页总资产可按位置拆分显示 |
| 数据来源 | 交易所位置由交易所记录推导；冷钱包与冷钱包理财由用户提供清单，账本不联网获取 |
| 理财利息 | 冷钱包理财产生的利息按白拿类记录，存放位置为冷钱包理财 |

托管型等量代换资产（如托管版以太币）按独立币种处理，不与原生币种合并计算平均购价。
