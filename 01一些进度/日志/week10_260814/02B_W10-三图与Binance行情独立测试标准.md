## 五、T1：原始 production 最短主链

使用独立端口和全新浏览器 origin，创建全新的加密测试账本。测试密码不得写入截图或 02C。

固定虚构事实：

- BTC 买入 1 @ 60000 USD。
- ETH 买入 2 @ 2000 USD。
- ADA 买入 1000 @ 0.5 USD。
- ADA 卖出 100 @ 0.55 USD。
- 同日手动 BTC 价格 70000 USD。

必须验证：

1. 三项默认映射可见。
2. 真实 Binance 刷新成功时，价格为正数，来源为 Binance，as-of 可见。
3. 不锁定具体价格数值；价格随市场变化不构成失败。
4. 自动模式同日选择 Binance，手动模式选择 BTC 手动价并让其他资产回退 Binance。
5. 持仓表、饼图和曲线使用同一价格结果。
6. 三图与热力日期筛选可操作。
7. 完成一次明文导出提示、clear、无刷新导入和重新解锁。

真实 Binance 因地域或网络不可用时，不把联网成功记为通过，也不直接判产品失败；记录外部限制并继续执行 T2。

## 六、T2：受控失败、限流与部分成功

使用临时测试副本，将真实 `BinanceMarketDataClient` 接到可控 `fetch`，不得用伪造页面替代真实组件。

| ID | 场景 | 必须结果 |
| --- | --- | --- |
| T2.1 | 请求超过 8 秒 | 页面报告超时，旧价和本地账本保留 |
| T2.2 | network error | 页面报告失败，本地交易和手动价格仍可新增 |
| T2.3 | HTTP 429 / 418 | 识别为限流，不重试、不清旧价 |
| T2.4 | HTTP 500 | 识别为外部 HTTP 错误，不写 `0` |
| T2.5 | BTC/ETH 成功、ADA 失败 | 只保存成功资产，逐项显示失败 |

全部场景共同通过线：

- 失败不得删除旧 API/manual 价格或映射。
- 不得写入 `0`、交易价、成本或未来价格代替市场价格。
- 手动价格和本地交易继续可用。
- 部分成功只产生一次账本 mutation。
- 页面成功数、失败数、逐资产原因与实际一致。
- 重新挂载后事实和失败前后的有效保存结果一致。

## 七、T3：旧未来事实纠正模式

## 十一、严重度与总判定

| 等级 | 定义 | 总结论影响 |
| --- | --- | --- |
| P0 | 数据不可恢复、明文秘密泄漏、错误删除其他数据 | 不通过，立即停止 |
| P1 | 旧响应覆盖新账本、未来事实进入计算、网络失败破坏本地可用性、可利用的生产高危漏洞 | 不通过 |
| P2 | 非核心显示/交互错误、已隔离的依赖风险、证据不完整但不破坏数据 | 有条件通过，交用户决定 |
| P3 | 轻微文案、视觉或非阻塞记录问题 | 可通过并记录 |

02C 总结论只能使用：

- **通过**：所有必测项完成，无 P0/P1/P2 遗留；P3 可记录。
- **有条件通过**：无 P0/P1，但存在已解释的 P2 或非阻塞外部限制。
- **不通过**：出现 P0/P1 或任何必测合同失败。
- **受阻**：源码状态、权限、浏览器或 advisory 使关键测试无法执行。

任何未执行的必测项不得算作通过。02C 还必须明确回答：
