## 日期与未来事实

### 日期归属

- 一条记录归属的自然日由记录值中的 `YYYY-MM-DD` 决定。
- `2026-07-25` 永远属于 7 月 25 日。
- `2026-07-25T19:00:00+08:00` 在热力图和日级曲线中也固定属于 7 月 25 日。
- 用户跨时区旅行或更换设备时，历史记录不得移动到另一个日期格子。
- 精确 datetime 的时区仍可用于判断事实先后，但不能重新解释记录所属日。
- 不接外部时间 API；“今天”由本地可注入时钟提供。

### 未来事实

- 新增交易不得晚于今天；未来交易属于录入错误。
- 新增手动价格和 Binance 价格快照不得晚于今天。
- 新导入账本包含未来交易或未来价格时，拒绝导入并指出具体错误。
- 旧版本已经保存的未来事实允许解锁、查看和救援导出，但在日期真正到来前不进入持仓汇总、三张图或当日统计，并显示明确警告。
- 未来限价单不预先生成未来 `Trade`。后续如果实现 `PendingOrder`，只能在真实成交后按实际成交时间生成交易事实。

## 价格来源与 Binance 行情

### 当前价格来源

Week 10 同时保留两类合法价格事实：

- 用户手动录入的 `PriceSnapshot`。
- Binance 公共市场数据生成的 API `PriceSnapshot`。

交易成交价仍不得自动充当市场价格。某资产从未存在合法价格快照时，只显示持仓成本，不显示或伪造市场价值。

### Binance 范围

- 使用 Binance 公共市场数据，不使用账户、下单、余额或任何私有 API。
- 本轮只读取最新价格，不拉取历史 Kline、OHLC 或分钟数据。
- 解锁并进入可写 Dashboard 后自动刷新一次。
- 页面提供真实的“刷新行情”按钮。
- 不做定时轮询，不做 WebSocket，不在后台持续请求。
- 多资产刷新允许部分成功：成功资产更新，失败资产保留旧 API 快照或回退手动价格，并逐项显示失败原因。
- Binance 不可达、超时或限流时不得清空旧价格、写入 `0` 或阻塞本地账本；降级路径可用即可通过外部可用性边界。

官方入口：

- [Binance Spot REST 公共市场数据说明](https://developers.binance.com/en/docs/products/spot/rest-api)
- [BTCUSDT exchangeInfo 示例](https://data-api.binance.vision/api/v3/exchangeInfo?symbol=BTCUSDT)

### 交易对映射

- 每个资产可以配置一个 Binance Spot 交易对，例如 `SOLUSDT`、`BNBUSDT`、`DOGEUSDT`。
- 配置由用户手动输入，保存前必须向 Binance 验证交易对存在、状态可交易、基础资产匹配、计价资产为 USDT。
- BTC、ETH、ADA 默认预置 `BTCUSDT`、`ETHUSDT`、`ADAUSDT`，但允许用户修改或移除。
- 行情映射属于完整账本配置，必须进入加密 IndexedDB 和明文备份；换设备导入后不得丢失。
- 删除映射只停止未来刷新，不删除已经形成的 API 价格快照。
- API 快照必须保留 Binance、交易对、原始 USDT 计价和获取时间等来源证据。

### 刷新与保存

- 同一资产同一记录日期最多保留一条 Binance API 快照。
- 同日再次刷新时更新该日 API 快照，不无限追加记录。
- 一次多资产刷新只形成一次批量账本变更和一次保存链。
- 刷新失败不污染 `LedgerData`；成功项与失败项分别报告。

### 来源开关

页面提供一个全局价格来源优先级开关：

```text
Binance 优先：优先使用 Binance；没有时回退手动价格
手动优先：优先使用手动价格；没有时回退 Binance
```

- 每次解锁默认使用“Binance 优先”。
- 开关同时控制持仓汇总、饼图和曲线，三处不得出现不同市值。
- 每个资产必须显示实际采用的来源和价格截至时间。
- 开关只是当前会话的展示偏好，不写入 `LedgerData`。
- 手动价格和 Binance 价格都保留；切换来源不得删除或覆盖另一类事实。

## 持仓市值饼图

- 饼图回答“当前 USD 等值持仓怎样分配”。
- 只统计当前非零持仓。
- 资产占比使用所选价格来源得出的当前可证明市值。
- 示例：BTC `5000`、ETH `3000`、ADA `2000`，占比分别为 50%、30%、20%。
- 买入、卖出、手动价格变化或 Binance 刷新后立即重新派生。
- 单资产显示 100%。
- 缺价资产不得以 `0` 进入占比，必须列为未估值资产。
- 部分可估值时，只表达已估值资产内部占比，并说明未进入占比的资产。
- 全部非零持仓缺价时显示缺价状态，不画误导性空饼图。
- USD/USDT 1:1 近似说明必须在图表旁常驻。

## 持仓市值与持仓成本曲线

- 曲线不是完整账户净值，不包含未记录现金、充值或提现。
- 两条线固定为“持仓总市值”和“剩余持仓成本”，不堆叠、不平滑。
- 持仓成本沿用现有 cost basis 规则，部分卖出后下降，暂不计手续费。
- 范围保留 `1日 / 7日 / 30日 / 365日 / 全部`。
- 7、30、365 日使用包含今天在内的连续自然日，每天生成一个日级点。
- 进入显示范围前，必须先重放更早事实，建立区间起点的真实持仓和最后已知价格。
- 没有新交易或新价格的日期沿用最后已知事实，阶梯线保持水平。
- “全部”从第一笔相关交易显示到今天。
- 1 日范围必须保留；没有可靠日内行情时整段显示水平线，不制造盘中波动。
- 1 日从未存在市场价格时，只画持仓成本水平线，市值线显示缺价。
- Binance 本轮只提供最新价格，因此接入前的历史仍由已有手动价格快照形成；API 快照只从实际获取日期开始影响曲线。
- 每个历史日期只能使用该日及之前的价格，禁止未来信息泄漏。
- 任一非零持仓缺价时，当日持仓总市值为缺失并断开；成本线继续显示。
- 已清仓资产的历史曲线继续保留，不能因为当前持仓为零而删除过去。

## 最近 365 天交易活跃热力图

### 范围与统计

- 显示今天及之前 364 个自然日，共 365 天。
- 每个格子代表一个记录日期。
- 只按交易笔数统计；买入和卖出都计入。
- 未来交易被禁止；旧未来事实在到期前也不进入统计。
- 悬停显示日期、总笔数、买入笔数和卖出笔数。

### 五档算法

五档由一个无亮度状态和四个非零亮度组成：

```text
level 0：0 笔
level 1：0 < 当日笔数 / 最大日笔数 <= 25%
level 2：25% < 比例 <= 50%
level 3：50% < 比例 <= 75%
level 4：75% < 比例 <= 100%
```

- 最大日笔数取最近 365 天内的最大值。
- 同样笔数必须得到同一等级。
- 当前最大笔数始终为 level 4。
- 只有一个非零交易日时，该日直接为 level 4。
- `1、1、1、30` 的样例中，三个 `1` 都是 level 1，`30` 是 level 4。
- 全部为零时，365 个格子全部为 level 0。
- 新增或删除交易后，全部等级立即重新计算，但不写入账本。

### 日期筛选

- 点击格子后，交易列表只显示该记录日期的交易。
- 再次点击同一天取消筛选。
- 页面提供明确的“清除日期筛选”入口。
- 新增或删除所选日期交易时，格子、提示和列表同步更新。
- 导入、清空或替换整个账本时重置筛选。
- 日期筛选属于会话 UI 状态，不写入 IndexedDB。

## 页面与技术边界

- 图表库正式使用 Apache ECharts，不使用 Recharts。
- 三图统一使用 Canvas renderer，关闭动画。
- ECharts 只负责展示，不承担持仓、价格、缺价、日期或热力等级计算。

- Decimal 字符串继续承担业务精度，只在 ECharts 渲染边界转换为有限 number。
- 页面先删除空侧栏、假导航、顶部假筛选、占位图和开发阶段英文标签。
- 品牌信息保留到页头；加密设置、解锁、重置和恢复继续属于既有访问门禁。
- 图表总览顶部放来源开关、刷新按钮、刷新状态和交易对配置。
- 来源、价格截至时间、USD/USDT 近似和失败降级必须在图表附近可见。
- 持仓表、饼图和曲线使用同一价格选择结果。
- 本轮不因 Binance 接入破坏手动价格、离线查看、加密保存、备份恢复或清空账本。
