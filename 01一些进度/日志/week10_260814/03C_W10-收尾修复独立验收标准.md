### T5-02：production V2 原始存储

```text
database: local-first-trading-ledger
store: ledger

```

```text

cryptoVersion
formatVersion
```

## 十三、T6：依赖与安全独立复核

### T6-01：正式命令

- 不运行任何自动修复，不改变 lockfile。

## 十四、P2 专项观察（不属于 T0–T6 硬通过线）

以下两项来自执行后代码审查，不属于 03B 原始核心合同，不单独把 T0–T6 判为 FAIL，但独立测试必须记录：

1. `OBS-01`：`ConfirmDeleteButton` 接受 Promise 回调。若受控 Promise reject 后出现未处理异常或永久 busy，且当前 production 调用链无法触发，只记 P2 剩余风险；若正式调用方已经存在可触发的异步拒绝路径，则按实际影响升级。
2. `OBS-02`：构造两条同类型、同资产、同时间的普通历史交易，检查删除按钮能否被读屏或 DOM 查询唯一识别。若只能依赖行视觉上下文而按钮名称重复，记 P2 无障碍问题。

这两项不得反向修改 03C 或源码；发现问题时总结果最高为“有条件通过”，除非实际可达性或数据影响要求升级为 P0/P1。

## 十五、严重度与总判定

| 等级 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 数据不可恢复、错误删除其他事实、明文秘密泄漏、加密边界被破坏 | 立即不通过 |
| P1 | 核心合同失败、旧响应污染新账本、未来事实进入计算、可达 production high/critical | 不通过 |
| P2 | 非核心但真实的交互、无障碍、异常处理问题，或有充分隔离证据的剩余依赖风险 | 有条件通过 |
| P3 | 轻微文案、视觉和记录问题 | 可通过并记录 |

`03D` 总结论只能使用：

- **通过**：T0–T6 全部硬测试项均为 `PASS`，无 P0/P1/P2；允许记录 P3。
- **有条件通过**：全部硬测试项为 `PASS` 或本文件明确允许的 `EXTERNAL_LIMIT / PASS_FALLBACK`，无 P0/P1，但存在已解释 P2、真实 Binance 外部限制或 audit fallback。
- **不通过**：存在 P0/P1，或任何已经执行的必测合同 FAIL。
- **受阻**：除 `EXTERNAL_LIMIT` 之外，源码基线、权限、production 浏览器、raw IndexedDB、audit/advisory 或证据链使任一硬测试项成为 `BLOCKED`。

判定顺序：

```text
P0
→ P1 或必测合同 FAIL
→ 普通必测项 BLOCKED
→ EXTERNAL_LIMIT / PASS_FALLBACK
→ P2 / P3
```

未经执行的必测项不得算 PASS。开发 AI 的既有结果不能填补本轮 `BLOCKED`。

`03D` 必须明确回答：

```text
当前是否可以进入合并审查：是 / 否
是否需要生成新一轮修复计划：是 / 否
```
