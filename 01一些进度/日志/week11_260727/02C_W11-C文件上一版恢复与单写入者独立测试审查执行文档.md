只检查 AbortSignal 或让旧 Promise 永不返回不算通过。

## 六、审查组 4：FILE-008 重新打开与重新连接

### 6.1 connection record 原始内容

直接读取相应 IndexedDB database / store / key，证明 record 只含：

- 连接合同版本；
- 结构化克隆的文件 handle；
- expected fileId 或等价少量身份。

不得出现：

- `LedgerData` 或完整加密 generation；
- 明文密码、CryptoKey、可直接解密材料；
- session token、永久锁、派生结果或页面状态。

record 只能在 C 完整验证并成为当前有效连接后更新；错密、取消、错误文件、恢复未确认或旧操作晚到不能覆盖它。

### 6.2 权限矩阵

必须逐项测试：

| 场景 | 预期 |
| --- | --- |
| 刷新后 `queryPermission(readwrite) = granted` | 进入同一 C 的解锁流程 |
| `prompt` | 显示明确“重新连接”；只在用户点击后 request |
| request 后 granted | 继续身份核对和解锁 |
| denied | 明确拒绝；不创建空账本、不回退 IndexedDB |
| handle / 文件被删除、移动或不可读取 | 明确不可用或重新连接；不创建空账本 |
| connection record 损坏 | fail closed；不自动清空或覆盖 |

### 6.3 重新选择

- 正确文件：新 handle 与 persisted handle `isSameEntry() = true`，fileId 等于 expected fileId，完整合同有效。
- 选错文件：实际文件不同或 fileId 不同，零写入、不替换 record。
- Finder 复制件：即使 fileId 相同，只要 `isSameEntry() = false`，不能作为“重新连接原 C”接受。
- persisted handle 已坏到无法比较：fileId 单独不能证明物理同一，重连 fail closed；只能通过明确“忘记连接并选择另一本账”退出原连接语义。
- 旧 permission、picker、inspect、unlock、recovery Promise 在取消、新选择、锁定、卸载后晚到，不能覆盖新 session。

任何失败都不得调用 `createInitialLedgerData()` 冒充原账本，不得产生空 C，不得静默进入 legacy IndexedDB。

选错文件仍可写入、失败生成空账本、只按 fileId 接受复制件或旧重连覆盖新选择，FILE-008 与整体 FAIL。

## 七、审查组 5：FILE-009 密码生命周期

### 7.1 建立和使用

独立核对：

- 新建密码只接受 12–128 个 Unicode code point；
- 不 trim、不 normalize；
- 两次输入逐字符一致；
- 11 / 129 拒绝，12 / 128 接受；

- 不存在找回密码、备用密码、管理员后门或绕过入口；
- 错密与认证失败使用通用提示，不泄露 previous / AAD 差异。

### 7.2 不落盘

通过源码、测试替身和真实存储共同确认：

- 明文密码不进入 connection IndexedDB、legacy IndexedDB、localStorage、sessionStorage、URL、日志、error report 或 React 业务 state；
- CryptoKey 不可导出，不写任何长期状态；
- C 外层只保留合同允许的 salt / crypto metadata，不额外复制可解密材料；
- 应用只承诺丢弃可达引用，不夸大为浏览器进程物理内存擦除。

### 7.3 刷新、关闭和立即锁定

先核对 02B 是否记录用户对 dirty 状态下立即锁定交互的明确决定。若没有决定而开发者自行加入二次确认、静默放弃或自动补保存，在没有其他确定性失败时，FILE-009 与整体 BLOCKED；独立 AI 不替用户选择。

必须覆盖：

1. 刷新后原 session 和密码材料不可复用，重新输入密码。
2. 关闭页面后浏览器释放 lease；重开仍需权限 / 重连和密码。
3. 按用户已确认的交互发出最终锁定动作后，UI / session generation 立即失效，回到安全入口。
4. dirty 行为与用户决定一致；没有擅自加入二次确认、静默放弃或额外保存策略。
5. 最终锁定动作先同步调用 session / Controller `beginQuiesce` 或等价边界，使旧 permission、picker、unlock、recovery 和新文件操作失效。
6. Hook 随即在返回 drain Promise 前同步禁新 mutation、推进 generation，再等待已接受的完整队列尾；测试同时覆盖已排队但尚未调用 Repository 的 save 和已经进入 Repository / 写锁的操作。
7. 收口完成前 lease 不释放；一次性、session-scoped quiesce token 或等价证明形成后，才丢弃 Repository / CryptoKey 可达引用并释放 lease，第二页面才可主动重试。
8. 队列中的旧结果不能重挂载、显示 saved 或恢复旧 session。
9. 锁定后旧 save、clear、recovery、permission、picker、unlock Promise 真正晚到时均被忽略。
10. active session 没有不带 quiesce 证明的公开 release；缺少、伪造、跨 session、重复 token 或旧 drain 都不能释放新 session。
11. 正常路由 / Gate 卸载走同一 drain-before-release 边界；崩溃依赖浏览器运行期释放，不写永久锁。
12. 没有闲置计时自动锁定功能被顺手加入。

密码落盘、锁定后旧 session 可继续解密 / 写入、lease 不释放、存在绕过入口或密码边界强制项失败，FILE-009 与整体 FAIL。
