### 2.3 旧 Promise 和 close 的真实释放

- slow A / fast B：先 resolve B，再真实 resolve A，最后解锁检查只能得到 B。
- 取消与创建新 C：在边界发生后真实 resolve A，再检查 `unlockSelected()`。
- Gate 卸载：组件 cleanup 发生后真实 resolve A，并 await Controller 的 selection Promise 完成。
- 旧失败清空：B 已成功发布后真实 reject A，再解锁检查 B。
- Hook：写入进入 `saving` 后真实释放 close；close 发布合法 S2 salt 变异，再执行同句柄 readback。

没有用 sleep、只检查 AbortSignal 或让旧 Promise 永久 pending。

### 3.1 完整 metadata 绑定

比较字段固定为：

```text
cryptoVersion
kdf.name
kdf.hash
kdf.iterations
kdf.saltBase64Url
cipher.name
cipher.keyLength
cipher.tagLength
```

比较不依赖对象引用或任意 `JSON.stringify` 字段顺序。create、普通 save、pending-intent reconcile 和 open 的 generation 验证都复用 `verifyLedgerFile(...)`；对于已绑定会话，磁盘 metadata 漂移在 generation 解密前失败。

### 3.2 operation generation

```text
select / create 开始
→ generation + 1，并清除旧 pending selection

cancel / Gate unmount
→ generation + 1，并清除当前 pending selection

异步 picker / inspect / create / unlock 返回
→ 仅 generation 仍为当前值时允许发布、清空或返回 session
→ 旧操作统一按取消或解锁失败退出，不修改较新状态
```

React `operationRef` 和 `mountedRef` 仍只承担 UI 职责，不再被当成 Controller 并发正确性证明。
