## 2. 同名文件“替换”规则更正

真实 Chrome 验收中，测试者在“新建 C”的系统 save picker 里选择了一个已存在的同名文件，并在操作系统显示替换确认后主动确认。文件随后被创建为新的空 C。

这属于正常的“另存为”语义：

```text
用户点击“新建 C”
→ 系统让用户选择目录和文件名
→ 同名文件存在
→ 系统询问是否替换
→ 用户取消：必须零写入
→ 用户主动确认替换：允许用新 C 替换该文件
```

此前 01A / 01C 把“系统已询问且用户已确认替换”也要求为零写入，超出了产品负责人的真实意图。产品负责人于 2026-07-29 明确确认正确规则后，01A / 01C 已依照 000 第 8 条记录合同更正。

因此，原报告草稿中的“P0-01 非空目标被覆盖”撤销。它不是代码 Finding，也不构成 FILE-002 失败。真正的失败条件仍是：

- 程序绕过系统 picker 静默覆盖；
- 用户取消替换后程序仍写入；
- 程序写入用户没有选择的另一个文件；
- 错误密码、损坏文件或取消选择后仍进入可写会话。

本轮没有出现这些行为。
