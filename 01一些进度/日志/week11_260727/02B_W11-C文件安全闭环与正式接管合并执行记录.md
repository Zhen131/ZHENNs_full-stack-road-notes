### 2.1 阶段二：dirty 状态立即锁定

用户明确选择 `B`：

> 先提醒“还有内容没保存”，让用户选择“重新保存”或“我确定不要了，继续锁定”。

实际行为：

- 没有未保存修改时，立即进入安全锁定。
- 有未保存修改时，第一次点击不锁定、不释放文件，先显示明确提醒。
- 用户可以重试保存、取消，或明确选择放弃未保存修改并继续锁定。
- 已经进入底层写入的操作仍按 quiesce / drain 合同收口，不进行危险的强行中断。

> 只读验证旧完整账本，把它写入一个全新的 C；完成 write、close、同文件 readback、身份和内容验证后，再经用户固定文本确认，原子删除那一条仍未变化的旧完整账本记录。

- 允许保存上次选择的文件句柄、少量 fileId / 连接身份及重新授权所需非敏感信息。

## 六、阶段三：FILE-003 / FILE-010

### 6.1 FILE-003：C 成为唯一正式完整账本

开发侧结果：`PASS`。

按用户决定 A 实现：

1. 若检测到 legacy `ledger:v1`，正常入口优先进入旧账本只读迁移，不允许绕到 remembered C 或空账本。
2. 旧密码只用于生成不可写的 migration candidate；不会发布 legacy autosave session。
3. 用户选择一个全新的 C 并设置 C 密码。
4. `createFromLegacy(...)` 把完整 LedgerData 写入新 C。
5. `verifyMigrationTarget(...)` 验证 write、close、同文件 readback、实际文件身份、fileId、revision 和完整内容。
6. 只有迁移回执仍有效且用户输入固定文本 `删除旧浏览器账本` 后，才生成一次性删除授权。
7. 删除前再次验证目标 C；旧记录使用同一 IndexedDB readwrite transaction 执行 `deleteIfUnchanged(expectedEnvelope)`。
8. 只有 transaction `oncomplete` 后才报告删除成功。

安全边界：

- 用户在创建 C 前取消、创建 / write / close / readback 失败、迁移验证失败、删除失败或旧 envelope 变化时，legacy 原样保留。
- 新 C 已创建但用户选择保留旧记录时，先安全释放未发布 C session；失败时保留同一 session 的重试能力。
- 页面卸载后晚到的迁移、验证或删除授权均不能删除 legacy 或发布 session。
- production composition 只暴露冻结的 legacy 只读迁移 / 条件删除白名单，不暴露旧 `setup / unlock / reset` 或完整 IndexedDB autosave 写链。
- 正常产品 session 只来自 C；展示、保存、重连、锁定和 clear 都围绕当前 C。
- legacy 与 connection 使用独立 Adapter / record；删除 legacy 不影响当前 C handle 登记。
- legacy 删除后，正常 C save / clear 不会重建完整 IndexedDB 账本。
- 三个 fake IndexedDB 取消 / 晚到测试直接比较 `ledger:v1` raw envelope 前后值；真实 composition 测试覆盖条件删除、source changed 和 connection record 不误删。

## 八、跨阶段组合问题与修复

开发过程中发现并关闭的关键组合问题：

1. 合法 clear authorization 可绕过 quiesced session 直接调用 raw Repository：新增 session 签发、WeakMap 绑定且必须同步 claim 的 execution context；锁定后无新 context，零写入拒绝。
2. 未同步 claim 的 driver 可能在微任务中晚到 claim：失败和同步 throw 均立即删除 context，Promise settle 后也删除；正式测试证明 late claim 为 false、零副作用。
3. clear 加密期间外部 R302 晚到：加密后、真正 write 前再次复读完整磁盘基线。
4. clear 在 intent 前失败、lease 拒绝、write / close 或不确定 readback：复用原 authorization / 同一 intent，但每次执行仍需新的一次性 context；不新增 generation。
5. clear 与立即锁定：quiesce 前已经准入的 clear 被 drain；测试在释放写锁 gate 前证明 token 尚未签发、lease 尚未释放。
6. 普通 save 失败后 clear：不丢失 dirty snapshot、原保存错误或 retry，不用清空伪装成功。
7. production 仍可能装配完整 legacy 写 Controller：改为冻结的 legacy-exit 白名单 facade。
8. 迁移删除失败不能安全重试：保留并复用同一删除 authorization，只对完全未变化的旧 envelope 重试。
9. 迁移 C 在卸载或验证晚到时 release 失败：保留同一 lifecycle owner / token / session，下一 Gate 显式重试。
10. 删除 authorization 在 Gate 卸载后晚到：在授权 await 后、任何 delete 前再次检查 operation generation；失效立即返回。
