## 八、矩阵 D：可疑重复

### D1. 相同 ID

同一 ID 必须是硬错误：

- 不进入可疑组；
- 不能被一次确认覆盖；
- import port 调用 0；
- C 与 B 不变。

### D2. 十进制语义

`0.10` 与 `0.1` 在 quantity/price/totalValue/fee 比较中按 decimal 语义相等。不得转换为 JS 浮点或只做字符串比较。

### D3. 时间边界

| 样例 | 预期 |
| --- | --- |
| 两笔都有精确时间，时间与核心字段相同 | 可疑 |
| 两笔都有精确时间，时间不同但同日同价同量 | 不可疑 |
| 至少一笔 day，同一自然日且核心字段相同 | 可疑 |
| 至少一笔 day，自然日不同 | 不可疑 |

minute 与 second 的具体值按真实 `occurredAt` 比较；不得只截自然日。

混合精度样例还要证明：先按上述规则建立真实可疑关系，再收成组；若一个 day 记录分别连接两个不同精确时间记录，组可以列出三者，但报告不能谎称两个精确时间记录彼此时间相同。

### D4. 等级

- 核心字段 + fee + feeCurrency 都相同：高度可疑。
- 核心字段相同，fee 或 feeCurrency 不同：一般可疑。
- 整组所有成员的 fee + feeCurrency 相同才是高度可疑；任一成员不同则整组为一般可疑。

`id`、createdAt、updatedAt、note、rawText、feeRuleId 的变化不得改变分组；ID 仍由 D1 单独处理。

### D5. 分组与合法拆单

- N 条完全相同交易只形成一个组并列出 N 个升序原索引；混合精度组保留真实触发边；
- 不产生 N×(N-1)/2 对；
- 虚构 BTC、ETH、ADA 在不同精确时间的合法拆单不提示；
- 费用差异只改变等级，不删除记录；
- 结果顺序可重复。

### D6. 交互

- 取消：零写。
- 无可疑组：不需要额外风险确认。
- 有可疑组：只允许对当前 B identity + 当前 group identity 一次明确确认。
- 重选、重新预检、session/revision 变化使确认失效。
- 确认后仍按原样导入全部 B，不修改、删除、合并或部分导入。
- 任何硬错误存在时，真实或伪造确认都不能写 C。

- 两个 implementation blocker 尚未实现可证明的严格方案，且候选正确停止阶段二；
- 关键永久正式测试缺失而源码不足以直接判 FAIL；
- 真实 Google Chrome、macOS picker、专用 B/C、权限、双页面、重开或 raw storage 不可得；
- 无法取得严格失败零写或生命周期取消机制的必要平台证据；
- 测试环境不允许完成必要但授权的本机隔离验证；
- runner/依赖/宿主基础设施失败且未证明候选违反合同。

自动化全绿、源码在 main、02D 没有发现 FAIL，都不能把 BLOCKED 改成 PASS。

## 十五、执行完成线

03C 只有在以下全部完成后结束：

- 冻结同一完整候选；
- A～G 全部执行或明确记录不可执行原因；
- 正式测试、质量门与真实 Chrome 证据均有可追溯记录；
- 审查前后双仓状态和关键哈希完成对比；
- 四个 IMPORT、两个阶段和整体分别判定；
- 03D 已生成；
- 没有修改候选源码、正式测试、00B、00D 或 Git 历史。

独立审查结束只交出 03D 和判定，不修候选。发现的新缺口进入 Finding；是否创建后续修复批次由用户决定。
