# Week 13 main UI 重构已确认设计记录

日期：2026-08-13

状态：`设计方向已确认；可以据此进入第一轮 UI 重构`

文档角色：本轮产品讨论的定稿记录；不是执行计划、不是实现报告、不是验收报告

适用轨道：`01一些进度/产出/LocalFirstTradingLedger/` 的长期产品 `main`

## 一、结论

本轮已经确定完整的桌面端 UI 方向，足以开始第一轮界面重构。后续不再为了精确色值、单个图标、每条边距或某张小卡片的一项字段继续空谈；这些低风险细节应在第一版真实界面出现后，根据可读性和实际操作感受调整。

新界面从当前纵向长页面改为固定左侧导航加右侧工作区。产品以 `Zhenn's Ledger` 为名称，使用暖白、淡奶油、香槟金和蜂蜜橙构成的轻柔桌面金融面板；首页负责总览，记账、交易、导入导出和设置分别进入独立工作区。业务逻辑、计算口径、数据格式、加密与持久化安全链不因本轮视觉重构而改变，唯一已经明确的规则调整是新建账本密码下限由 12 个字符改为 8 个字符。

用户对本轮方向的核心表述是：

> 电脑端应该有左侧任务栏，不同界面对应不同功能。

> 决策成本一高了，他就不想用了这种 APP。

> 动效要让用户感知已经记上去了，不然会反复点击。

> 今天没有必要一步把 UI 做好，先把大概的样子和弄法固定下来。

## 二、当前问题与重构目标

### 2.1 当前界面的事实

- 解锁后的功能依次纵向堆叠：行情与估值、图表、盈亏摘要、持仓与价格、交易表单、手续费规则、交易列表和数据管理。
- 图表和交易热力图占用过大；Binance 配置等低频操作抢占首页注意力；新增交易反而位于长页面后部。
- 页面依赖整页滚轮移动，缺少桌面应用应有的稳定导航、工作区和主次关系。
- 入口和错误文案大量使用开发代号 `C`，用户无法从“选择 C”“C 核心密码”理解它就是账本。
- 当前交易表有十列，平台、手续费规则来源等低频信息与核心交易信息同权展示。
- 交易和价格表单的草稿保存在组件内部；如果新导航通过反复卸载页面实现，可能丢失草稿并重复触发 Binance 自动刷新。

### 2.2 本轮目标

- 第一眼知道当前账本情况和下一步能做什么。
- 日常记录交易尽量少点、少选、少重复输入，并给出明确的文件保存反馈。
- 首页在正常桌面窗口内形成完整总览，不再依赖整页上下滚动。
- 低频配置离开首页，但所有既有安全能力和异常状态继续可见、可操作。
- 视觉耐看、清楚、轻柔，有适度的 macOS 式反馈，不做展示型炫技界面。

## 三、产品名称、账本入口与密码

### 3.1 命名规则

- 产品显示名固定为 `Zhenn's Ledger`，暂不设计 Logo。
- 用户界面不得再出现开发代号 `C`；`C` 只可保留在历史文档、内部合同、源码类型或测试语境中。
- `.lftl` 只在解释文件格式和安全边界时出现，不塞入大标题或主要按钮。
- 用户概念统一为“账本”或需要强调安全属性时的“加密账本”。

### 3.2 选择与新建

选择页固定为：

- 品牌：`Zhenn's Ledger`
- 标题：`选择或新建账本`
- 主按钮：`选择账本`
- 次按钮：`新建账本`
- 说明：完整账本只保存在用户选择的加密 `.lftl` 文件中；浏览器只记住连接所需的少量信息。

把“选择账本”设为主操作，因为长期使用时打开已有账本远多于新建账本，也能降低误建空账本的概率。

创建页固定为：

- 标题：`新建加密账本`
- 密码框：`设置账本密码`
- 确认框：`再次输入账本密码`
- 提示：`至少 8 个字符，建议使用更长、容易记住但不易猜到的密码。`
- 主按钮：`选择保存位置并创建`
- 次按钮：`返回`

密码规则固定为 8—128 个 Unicode 字符。界面写“字符”，不得写成“8 位数字”。创建页清楚说明目前没有恢复码或后门，忘记密码后无法再打开账本，但不额外要求勾选“我已知晓”。密码管理器和 Touch ID 自动填充延期，不进入本轮。

### 3.3 解锁、重连与恢复文案

现有安全状态全部保留并改成人话：

- `重新连接上次账本`
- `重新选择上次的账本文件`
- `忘记上次连接并选择其他账本`
- `上次使用的账本暂时不可用`
- `解锁账本`
- 密码框：`账本密码`
- `正在安全锁定`
- `安全释放尚未完成`
- `确认恢复上一版`

需要重新授权上次账本时，`重新连接上次账本`是主按钮；重新选择文件是次要操作；忘记连接使用较弱但清楚的红色文字。入口阶段继续使用居中单卡片，不提前显示解锁后的侧栏。

## 四、整体视觉语言

### 4.1 参考与风格

- 主要参考用户提供的第二张 Paynix 仪表盘图片，吸收其桌面布局、卡片比例和柔和留白，不照抄紫色、头像、通知、搜索和不存在的功能。
- 风格定义为“轻柔但清楚”的浅色桌面金融面板，比重度拟态更接近轻量柔和卡片。
- 只让一级卡片轻微浮起；表格、输入框和卡片内部保持平整、边界清楚。
- 不做重度透明、重度背景模糊、所有控件都鼓起或凹陷的拟态，也不做持续漂浮、呼吸光和循环渐变。

### 4.2 颜色

- 页面外层：窄幅暖金色背景。
- 应用外壳：暖白。
- 左侧栏：比内容区稍深的淡奶油色。
- 品牌强调：低饱和的香槟金到蜂蜜橙。
- 主按钮：可承载白字的较深焦糖金。
- 盈利：绿色；亏损和错误：红色；品牌橙不得同时充当警告色。
- 当前总市值卡可以使用极淡香槟金底；其余摘要卡保持暖白。
- 暂不做深色模式。

### 4.3 字体、圆角与数字

- 使用 macOS 系统字体；中文优先由苹方显示，不从网络加载第三方字体。
- 金额、数量和表格数字启用等宽数字，便于纵向比较。
- 一级卡片圆角约 18—20px；按钮和输入框约 10—12px，最终值可在真实界面中微调。
- 金额概览默认保留两位小数并使用千位分隔；BTC、ETH、ADA 数量按需要保留更多位。
- 只格式化显示，不改写账本保存的原始精度。

### 4.4 图标

- 采用粗细一致的单色线性 SVG 图标，直接保存在项目内；第一轮不新增整套图标依赖。
- 图标只辅助扫视，中文文字负责解释，不使用纯图标导航。
- 未选中图标为灰褐色；选中后图标和文字一起变为深焦糖色。

## 五、桌面应用外壳与导航

### 5.1 固定结构

- 大屏外层保留约 12—16px 的暖金色窄边，内部是大圆角应用外壳。
- 左侧导航约 180—200px，固定不随右侧内容滚动，也不需要折叠。
- 右侧为独立工作区；正常页面滚动只发生在右侧内容区域。
- 顶部左侧只显示当前页名；右侧始终显示真实文件状态：`已保存 / 正在保存 / 保存失败`。
- 不放无功能的全局搜索、通知、头像或账号入口。

### 5.2 导航项目

主导航：

1. 首页
2. 记账
3. 交易

工具导航：

4. 导入与导出
5. 设置

左下角固定 `锁定账本`。未选项目不使用一排卡片边框；当前项目用低饱和金橙圆角条选中。暂不增加“资产”和“行情”顶级页面；当前价格能力还不是历史 K 线和资产详情完整的行情中心。

### 5.3 锁定行为

- 账本已保存且交易、价格草稿均为空：点击一次立即安全锁定。
- 有未完成草稿、正在保存或保存失败：才显示确认，说明继续锁定的影响。
- 锁定后回到当前账本的密码入口，不默认回到“选择或新建账本”。
- 锁定不会删除文件、忘记连接或清空账本。

## 六、首页

### 6.1 一屏结构

1280×800 是主要设计与验收尺寸。正常有数据首页在该尺寸下不需要整页纵向滚动，结构固定为：

```text
┌──────────────────────────────────────────────────────────────────────┐
│  Zhenn's Ledger     │  首页                              ● 已保存     │
│                     ├────────────────────────────────────────────────┤
│  首页               │ [当前总市值] [剩余成本] [未实现盈亏] [已实现盈亏] │
│  记账               │                                                │
│  交易               │ [ 总市值 / 剩余成本趋势图     ] [记一笔交易]    │
│                     │ [                             ] [资产分布   ]    │
│  导入与导出          │                                                │
│  设置               │ [持仓概览]   [交易热力图]   [最近交易]          │
│                     │                                                │
│  锁定账本            │                                                │
└──────────────────────────────────────────────────────────────────────┘
```

建议比例：右侧内边距约 24px；标题栏约 48—52px；摘要卡约 105—115px；趋势图约 290px；底部三张卡约 170px；卡片间距约 14—16px。它们是第一轮布局基准，不是禁止视觉调试的绝对像素合同。

### 6.2 顶部四张摘要卡

四张等宽卡固定为：

1. 当前总市值
2. 剩余持仓成本
3. 未实现盈亏
4. 已实现盈亏

`当前总市值`使用极淡金色底，其余暖白；四张卡不改变尺寸。卡片不展示当前没有既有计算依据的“较上周 +12.5%”等假指标。缺价资产必须紧邻总市值说明哪些资产未计入，不得按零处理。

### 6.3 中部趋势图

- 左侧约占中部宽度三分之二，比较“当前总市值”和“剩余持仓成本”。
- 默认时间范围为最近 30 日；保留 `1 日、7 日、30 日、365 日、全部`。
- 右上角只显示两个紧凑选择框：`自动选择`和`最近30日`，不铺开七个按钮。
- 价格模式准确命名为：
  - `自动选择`：比较手动价格和 Binance 价格日期，采用更新者；同一天采用 Binance。
  - `优先手动`：存在手动价格时优先使用；没有手动价格时仍回退 Binance。
- 显示每项资产最终采用的价格来源和日期，避免口径不透明。
- 总市值使用蜂蜜橙实线和极淡面积；剩余成本使用灰褐虚线；数据点平时隐藏，悬停时显示准确日期和金额。

### 6.4 右侧快捷入口与资产分布

- 右上卡片是唯一快捷入口，整张卡都可点击，标题 `记一笔交易`，小字 `记录买入或卖出`。
- 点击后切换左侧选中项到“记账”，进入同一个正式记账页并聚焦新增交易表单；不创建首页表单、第二套记账逻辑或第二份草稿。
- 入口卡可使用淡香槟金到蜂蜜橙渐变，是首页少数允许明显品牌色的区域。
- 右下为紧凑资产分布圆环；右侧列资产名称、比例和金额；缺价资产单独标记“未计入”。
- 资产分布不承担持仓详情跳转，避免与下方持仓概览重复。

### 6.5 底部三张卡

- `持仓概览`：按当前市值展示前三项；缺价资产不参与排名，但必须提示。具体每行最终显示“数量、市值、成本、未实现盈亏”中的哪三个字段尚未确认，第一版可在真实空间中决定。
- `交易热力图`：完整覆盖最近 365 天，压缩为小卡；采用浅奶油到深金橙的五级色阶。点击某天进入交易页并筛选到该准确日期。
- `最近交易`：显示最新 3—4 笔。点击某笔后进入交易页、定位并展开该笔；`查看全部`进入未筛选的完整交易列表。
- 三张卡内部不再产生独立纵向滚动条；超出内容进入对应完整视图。

### 6.6 空账本与缺价状态

- 不使用首次教程弹窗。
- 全新空账本保留整体外壳，在原趋势图位置显示 `还没有交易记录`和主按钮 `记录第一笔交易`。
- 点击后进入正式记账页并聚焦新增交易。
- 保存第一笔交易后，首页自然切换为正常仪表盘。
- 已有交易但缺少价格时，不再显示新手引导；在总市值和图表旁明确提示缺少价格，并提供进入记账页更新价格的入口。

### 6.7 完整持仓详情

- 不增加“资产”侧栏项目。
- 点击 `查看全部持仓`后，持仓卡在右侧内容区扩展为完整持仓详情；左侧导航保持可见。
- 展开使用约 200ms 的轻量果冻式缩放与淡入；关闭使用 `×`、Escape 或点击面板外空白。
- 关闭后焦点回到原持仓卡；切换侧栏也关闭详情；减少动态效果时直接展开。
- 完整表继续显示现有全部信息：资产、数量、含费平均成本、剩余成本、已实现盈亏、当前价格、市值和未实现盈亏。

## 七、记账页

### 7.1 页面结构

记账页是记录新事实的唯一工作区，两张表单同时可见，不使用标签页：

- 左侧较宽：`新增交易`
- 右侧较窄：`更新当前价格`

交易会改变持仓和成本；价格记录只改变估值和图表，不改变持仓数量。页面应使用短说明把这一区别说清楚。

### 7.2 新增交易顺序

表单按真实录入顺序分三段：

1. 买入 / 卖出、日期、资产。
2. 数量、成交均价、成交金额。
3. 平台、实际手续费、手续费规则和可选备注。

底部固定显示成交金额、手续费和实际支出 / 净到账摘要，再执行保存。

### 7.3 买入与卖出

- 使用并排的 `买入｜卖出` 两个切换按钮，彻底取消类型下拉框。
- 新表单永远默认买入；即使上一笔是卖出，保存后也恢复买入。
- 买入使用柔和绿色选中状态，卖出使用柔和红色选中状态；品牌金色不混入交易方向。
- 切换买卖不清空其他已填写字段。

### 7.4 日期与核心金额

- 交易日期默认今天，不记忆上一笔日期；补录历史交易时可修改为过去日期。
- 数量、成交均价和成交金额显示为横向公式：

```text
数量 × 成交均价 = 成交金额（不含手续费）
```

- 填完数量和成交均价后自动计算成交金额，但允许用户修改。
- 用户手动修改成交金额后，后续输入不得悄悄覆盖；旁边提供 `按数量 × 均价重新计算`。
- 原有一致性误差校验继续生效；错误直接指出三者不一致，不修改业务容差。

### 7.5 平台、手续费与备注

- 平台改为“建议列表 + 可手填”：优先列出手续费规则中已有平台，也允许记录新平台；最终仍保存现有平台文字，不新增平台数据合同。
- 实际手续费输入框始终可见，最终以用户确认的实际费用为准。
- 手续费规则正常时收起为一行候选，例如 `预计手续费 2.00 USDT · 来自 Binance 现货规则`；冲突或错误时才展开完整处理区。
- 规则 ID、公式和来源追踪放入规则详情，不占据日常表单主区。
- 交易备注默认收起为 `＋ 添加备注`；展开并输入后保持可见。

### 7.6 保存后的状态

交易保存成功后：

- 类型恢复买入。
- 日期恢复今天。
- 保留资产和平台，方便连续录入。
- 清空数量、成交均价、成交金额、手续费和备注。
- 成交金额恢复自动计算状态。

保存反馈必须区分“已经点击”和“文件真正保存”：

1. 点击后按钮立刻变成 `正在保存…`并禁止重复点击。
2. 文件认证保存成功后显示绿色对勾和 `交易已保存`。
3. 新增交易卡做一次约 180—220ms 的轻微放大回弹。
4. 保存失败不播放成功动画；明确写明交易仍在内存、文件尚未保存，并引导重试保存，不能让用户重复新增同一笔。

### 7.7 更新当前价格

右侧卡内分为两段：

- `Binance 价格`：显示本次解锁最近更新时间、成功 / 失败状态和 `立即更新`。一次更新所有已配置且有非零持仓的资产。
- `手动记录价格`：资产、当前价格、日期和按需展开的备注。

计价货币显示在价格输入框右侧，例如 `70,000 [USDT]`，不再占据单独只读输入框。手动保存同样使用防重复点击、成功对勾和轻微弹动。

手动价格日期的规则与交易不同：首次进入默认今天；保存后在当前解锁期间记住刚才的日期，方便补录同一天多个资产；锁定、关闭或切换账本后重新默认今天。保存后可保留当前资产，清空价格和备注。

### 7.8 草稿与 Binance 生命周期

- 同一次解锁期间切换页面，不丢失交易或价格草稿。
- 草稿只保存在内存，不写入 `.lftl`、备份或导出文件。
- 保存成功、主动重置、锁定或切换账本时才清空相应草稿。
- 每次解锁后自动刷新一次 Binance 当前持仓价格；同一次解锁期间切换页面不得重复自动刷新。
- 手动刷新始终可用。刷新失败不阻止打开账本，继续显示上次保存价格并明确标注本次更新失败。

## 八、交易页

### 8.1 列表与筛选

- 使用经典横向表格，不做每笔一张大卡片。
- 默认展示全部交易，不分页、不做“加载更多”。
- 最新交易在最上，越向下越早，最底部为最老交易。
- 交易内容在右侧工作区内部纵向滚动；表头和筛选栏固定，侧栏不动；显示正常滚动条。
- 顶部漏斗图标旁直接显示：`时间：全部｜日期：任意｜资产：全部｜类型：全部`。
- 时间快捷项为全部、今天、最近 7 天、最近 1 年；同时支持准确单日。
- 只有存在筛选时显示 `清除筛选`。离开后再返回恢复“全部交易、最新在前”。

### 8.2 主行信息与详情

主行顺序固定为：

```text
日期 → 类型 → 资产 → 成交金额 → 手续费 → 详情 → 删除
```

- 日期使用完整年月日，不使用“3 天前”等会变化的相对时间。
- 成交金额只显示不含手续费的交易金额，不混入实际支出 / 净到账。
- 适中密度，每屏约 8—10 笔。
- 点击整行或灰色 `详情`按钮，展开数量、成交均价、平台、手续费来源、现金影响和备注。
- 本轮不实现交易编辑，也不放禁用或点不动的假编辑按钮。未来实现真实编辑时，可以占用当前详情按钮位置。

### 8.3 果冻删除、倒计时与撤回

删除行为按用户提出的交互固定，不能简化为普通确认弹窗：

1. 行尾初始为两个等宽按钮：灰色 `详情`和红色 `删除`。
2. 第一次点击 `删除`，红色按钮以约 200ms 的果冻弹性向左扩展为两倍宽，覆盖原 `详情`按钮，文字改为 `再次点击删除`。
3. 此时点击该红色区域之外的空白，按钮缩回原宽度，不删除任何数据。
4. 第二次点击扩展后的红色区域，该行变灰，进入 5 秒待删除状态；行内显示倒计时进度条和 `撤回`。
5. 5 秒内点击撤回，恢复原行和原按钮，不产生数据变更。
6. 5 秒结束后才调用现有安全删除并进入文件保存；不是先删再制造反向数据。
7. 同一时间只允许一笔交易进入待删除倒计时。
8. 倒计时期间该行不能展开详情或触发其他操作。
9. 倒计时期间切换页面、锁定或使撤回入口不可见时，自动取消删除，不允许后台偷偷完成。
10. 如果现有持仓时间线规则拒绝删除，例如删除后导致后续卖出超过持仓，则恢复该行并清楚说明原因，不显示假成功。
11. 删除完成后显示 `交易已删除`，右上角全局状态继续反映文件是否真正保存。
12. 系统开启减少动态效果时，确认按钮直接变宽、进度条正常推进，不播放果冻弹性。

## 九、导入与导出

### 9.1 页面结构

- 顶部始终显示安全警告：这里导出的是包含完整账本内容的明文文件，不受账本密码保护，不应放入不可信或公开同步位置。
- 下方左右并排：左侧较窄为 `导出明文账本`，右侧较宽为 `导入明文账本`。
- 不把明文备份称为加密 `.lftl`，避免错误安全预期。

### 9.2 导出

- 显示将导出的内容范围和风险。
- 提供单一明确按钮 `导出明文账本`。
- 不增加虚假的加密导出选项。

### 9.3 导入

在右侧同一面板内分阶段显示：

1. 选择明文备份文件。
2. 零写入预检，显示通过项、警告、可疑重复组和阻止原因。
3. 满足现有安全条件后才显示 `完整替换当前账本`。
4. 用户再次确认后执行整本替换；失败时当前账本保持不变。
5. 成功后显示导入数量摘要和真实保存状态。

不使用多个弹窗承载长报告，也不把所有阶段一次性铺成文字墙。现有预检、完整替换、失败关闭和零静默合并规则不变。

## 十、设置页

设置页顶部固定三个文字切换，一次只显示一类：

1. 行情与交易对
2. 手续费规则
3. 危险操作

### 10.1 行情与交易对

- 使用紧凑表格：`资产｜当前交易对｜验证状态｜最近使用结果｜操作`。
- 修改时只展开当前一行的编辑与验证区。
- 页面明确说明只向 Binance 发送公开交易对代码，不发送交易、持仓数量、成本、密码或完整账本。
- 此处只负责配置；日常刷新按钮留在记账页；首页价格模式也不在设置中重复一套。

### 10.2 手续费规则

- 采用左侧约 40% 规则列表、右侧约 60% 新增 / 详情面板。
- 左侧只显示规则名、平台、资产、固定费 / 比例和启用状态。
- 右侧默认显示新增规则；选中已有规则后显示完整来源、创建时间和版本关系。
- 启用规则可创建新版本或停用；不引入直接修改旧规则，继续遵守现有版本替换规则。
- 冲突提醒只在确有冲突时出现在顶部。

### 10.3 危险操作

- 标题统一为 `清空当前账本内容`，不得出现 `C`。
- 明确说明会清空当前账本中的交易、价格和手续费规则，但不会删除 `.lftl` 文件本身。
- 初始只显示浅红边框按钮；点开后才显示详细影响、备份建议和确认文字输入框。
- 固定确认文字改为 `清空账本`。
- 不增加当前不存在的“删除账本文件”能力。

## 十一、反馈、动效与可访问性

### 11.1 反馈原则

- 日常操作采用“就地反馈 + 全局保存状态”。
- 普通成功提示可在数秒后淡出；保存失败、只读、兼容性、缺价、外部变更等重要状态持续显示，直到问题解决。
- 弹窗只用于确有必要的危险确认，例如完整覆盖导入和清空账本；记账不使用频繁弹窗。
- 所有写操作必须区分内存已接受、正在保存、文件已认证保存和保存失败，不能在文件落盘前宣称完成。

### 11.2 动效原则

- 总体强度固定为“克制但有手感”。
- 保存、持仓展开和删除确认使用短促弹性反馈；侧栏切换只做轻微淡入和平移。
- 不让数字、图表或卡片持续跳动。
- 所有关键动效支持 `prefers-reduced-motion`；关闭动画后仍保留文字、颜色、对勾和进度等非动态反馈。

### 11.3 可访问性与键盘

- 输入框、按钮和选中状态必须具有清楚边界，不能只靠阴影表达可操作性。
- 盈亏、警告和错误不能只靠红绿或金橙颜色区分，必须同时有文字或图标。
- 持仓详情支持 Escape 关闭并恢复焦点；表格展开和删除按钮具备准确可访问名称。
- 禁用按钮必须说明原因或邻近显示原因，不用低对比度把信息完全隐藏。

## 十二、响应式边界

- 本轮只做桌面端主设计，不单独设计手机版。
- 1280×800 及更宽：正常首页一屏完整显示，扩大窗口时增加留白，不让卡片无限变大。
- 低于约 1100px：摘要卡允许变为两行，右侧内容允许纵向滚动。
- 更窄时卡片继续自然上下排列；左侧栏仍保留中文文字，不收成难以理解的纯图标。
- 整个应用不得产生横向滚动；交易表等确需宽度的局部区域可独立横向滚动。
- 既有 390px 无整页横向溢出基线不得回归，但本轮不追求移动端专门交互。

## 十三、工程与安全边界

本文件只确定产品与交互方向，不授权改变下列合同：

- 持仓、成本、已实现 / 未实现盈亏和手续费计算口径。
- `LedgerData`、`.lftl`、BackupEnvelope 和现有事实数据格式。
- 加密算法、认证、current / previous、复读校验、锁定与安全释放。
- 文件连接、权限、并发、外部 revision、防覆盖和恢复上一版规则。
- 明文导入预检、整本替换、失败零写入和可疑重复处理。
- 旧 USD、V1、legacy、未来事实纠错和只读状态的现有安全边界。

实现新导航时必须维持同一个解锁会话和持久化控制器，不能通过切换页面反复重建账本会话。交易 / 价格草稿和 Binance 刷新控制应提升到当前解锁会话可持续的位置，避免切页丢失草稿或重复联网。

第一轮默认不增加第三方动画库或图标库；优先使用 CSS 动效和项目内 SVG。只有真实实现证明现有能力不足时，才单独讨论依赖。

## 十四、明确延期与尚未确认

### 14.1 明确不进入第一轮

- Google Password Manager、Touch ID 或其他密码自动填充集成。
- 交易编辑；交易行不放禁用的假编辑按钮。
- 独立资产页、完整行情中心、历史 K 线和资产详情。
- 全局搜索、通知系统、用户头像、账号体系和深色模式。
- Logo 设计。
- 新的业务指标、收益率百分比或假占位数据。
- 业务逻辑、加密、持久化安全链和数据格式重写。

### 14.2 可以在第一版后调整的细节

- 首页持仓概览每行最终显示“数量、市值、剩余成本、未实现盈亏”中的哪三个字段。
- 精确 HEX 色值、阴影强度、最终圆角、卡片像素高度和局部间距。
- 各导航项和操作按钮的具体 SVG 图形。
- 果冻动效的最终 easing、轻微缩放比例和持续时间微调。
- 表格列宽、文字截断和小窗口下的局部排列。

这些细节不阻塞第一轮 UI 重构。第一版应先让真实页面达到“结构正确、主次清楚、日常路径顺手、安全状态不丢”，再依据截图和实际使用调整视觉数值。

## 十五、后续使用规则

- 本文件是后续正式 UI 执行计划的设计输入，不直接承担阶段拆分、文件清单、测试命令、提交批次或验收报告职责。
- 真正开始实施前，应从本文件提取一个独立执行计划，明确第一轮修改范围、组件拆分、安全回归、浏览器验收和 Git 提交边界。
- 第一轮不要求一次完成所有细节；优先完成应用外壳、导航、首页、记账与交易主流程，再以真实界面截图决定低风险视觉微调。
- 如果实现中发现本文件与现有安全合同冲突，安全合同优先；不得为了动效或布局削弱失败关闭、认证保存和用户可见错误。

## 十六、自检表

| 问题 | 后续必须满足 |
