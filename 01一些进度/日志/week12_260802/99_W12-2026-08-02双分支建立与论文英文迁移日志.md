## 昨天最重要的结果

我昨天真正解决的并不是某一个新功能，而是把之前缠在一起的长期账本和毕业论文重新拆开了。

原来我一直把它们当成同一个项目去推进，所以我一方面想让账本满足自己长期真实使用，另一方面又想让它尽快回到论文方案和导师能够检查的范围。两个目标本身都没有错，但是放在同一个分支里以后，我每做一个决定都要同时考虑长期产品、论文、比赛和课程，结果就是东西越做越多，下一步反而越来越不清楚。

现在我把这件事情定下来了：`main` 继续做我长期会用的真实账本，`CS2026` 专门完成毕业论文。两条线共享同一个历史起点，但是以后各走各的，不互相合并，也不让 AI 自动把一边的修改搬到另一边。这样以后我坐到电脑前，不需要再同时处理四五件事情，只需要先判断今天是在做账本，还是在做论文。

## 昨天完成了什么

### 1. 先把论文方案和当前源码做了对照

我先把原毕业方案和当前源码逐项对照，整理出了三个表：

- 原方案核心功能哪些已经有、哪些只有一部分、哪些还没有。
- 原技术栈和当前真实技术栈发生了哪些变化。
- 原方案之外，我已经额外做出了哪些能力。

这份对照保存在 `000-截至2026-08-02的毕业论文原方案与当前源码对照.md`。它的意义不是证明我做了很多，而是让我以后能够很直观地看见：论文最低要求还差什么，哪些长期产品功能不应该继续塞进论文主线。

### 2. 固定共同基线，建立两个长期 worktree

我把源码提交 `084ae7d` 固定成 annotated tag：

```text
CS2026-baseline-2026-08-02
```

然后建立了两个长期目录：

| 方向 | 本地目录 | 分支 | 用途 |
| --- | --- | --- | --- |
| 长期账本 | `LocalFirstTradingLedger/` | `main` | 我自己长期真实使用的产品 |
| 毕业论文 | `LocalFirstTradingLedger-CS2026/` | `CS2026` | 论文实现、实验和导师检查 |

它们是同一个源码仓库的两个 worktree，不是两个互相复制的仓库。两个分支都已经推送到 GitHub，默认分支继续保持 `main`。

### 3. 把 main 的公开说明改成英文

`main` 仍然允许保留中文产品界面，因为这是我自己长期使用时的产品选择。但是 README、模块 README、`AGENTS.md` 和今后的提交标题统一使用英文，让源码仓库面对导师或公开读者时不会再显得中英文规则混乱。

这次没有为了形式去翻译 `main` 的界面、测试和源码注释，也没有改变任何业务逻辑。

### 4. 把 CS2026 当前工作树迁移成全英文

论文 worktree 的要求更严格：当前受 Git 管理的文档、界面、按钮、表格、图表、无障碍名称、错误信息、安全警告、源码注释、测试和永久夹具全部改成英文。

三个危险操作的确认文本也固定成了：

```text
CLEAR CURRENT C LEDGER
CLEAR LOCAL LEDGER
DELETE LEGACY BROWSER LEDGER
```

这次只做语言和内部命名迁移，没有改变 `LedgerData` schema、备份格式、`.lftl` 格式、错误码和业务计算规则。旧账本中的中文 `rawText` 仍然必须能够读取和重新导出，所以兼容测试使用 Unicode escape 保留了这条能力，而不是简单地把中文数据支持删掉。

### 5. 完成自动化验证，但没有冒充完整人工验收

`CS2026` 最终验证结果是：

- 受 Git 管理的当前工作树中文字符扫描为零。
- 55 个测试文件、698 项测试全部通过。
- typecheck、lint、production build 和 whitespace 检查全部通过。
- 浏览器检查了 Select/Create C 入口、新建 C 表单、密码不一致提示和无障碍名称，显示均为英文，控制台没有错误。

但是原生文件选择器之后的内部 Dashboard 没有取得完整人工巡检证据。自动化测试通过不能代替这条人工证据，所以我把它保留为待补项，没有写成“全部人工验收完成”。同样，原来的 `02D` 和 `03B` 仍然是 `BLOCKED`，不会因为建了论文分支就自动变成通过。

### 6. 把以后怎么维护写成了正式规则

我更新了根 `AGENTS.md`、当前开发状态、AI 使用指南、账本上下文说明和 `ledger-workflow` Skill，并新建了 `001_W12-main与CS2026双分支维护规则.md`。

以后默认路由是：

- 我说“继续论文”、提到“论文”或 `CS2026`，只进入论文 worktree。
- 我说“继续账本”、只说“账本”或没有提论文，只进入 `main`。

- AI 不得自动 merge、rebase、cherry-pick、复制修复或同时修改两个分支。
- 如果一边发现的问题可能对另一边有用，只记录“可能值得参考”，等我明确批准后再处理。

Skill 的 `agents/openai.yaml` 已重新生成，官方 `quick_validate.py` 验证通过；“继续账本”“继续论文”“论文 Git”三种只读路由也都检查过。
