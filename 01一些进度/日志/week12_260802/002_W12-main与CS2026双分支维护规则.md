## 任务路由

| 用户说法 | 唯一目标 |
| --- | --- |
| “继续论文”、任何含“论文”的任务、`CS2026` | `LocalFirstTradingLedger-CS2026/` 与 `CS2026` |
| “继续账本”、只说“账本”、完全没有提论文 | `LocalFirstTradingLedger/` 与 `main` |
| “论文 Git” | 只检查和报告 `CS2026`，不得碰 `main` |

任何写入、暂存或提交之前，都必须同时核对工作目录和实际分支。目录与分支不一致时立即停止修改，先修正定位。

## 禁止自动跨分支

- 不创建 `main` 与 `CS2026` 之间的合并 PR。
- AI 不得自动 merge、rebase、cherry-pick、复制修复或同时修改两条分支。
- 某条分支发现的问题可能对另一条有帮助时，只能在当周日志记录“可能值得参考”。
- 只有用户明确批准后，才能在另一条分支重新实现或复制改动；批准一个分支的修改不等于批准另一分支。
- 两条分支的状态、diff、测试、提交和推送必须分别报告，不得用一条分支的绿灯代表另一条分支。

## 语言规则

### main

- README、模块 README、`AGENTS.md`、Release Notes 和提交标题使用英文。
- 生产界面允许中文，这是长期产品的主动选择。
- 本轮不翻译源码注释、测试和中文产品界面。

### CS2026

- 当前受 Git 管理的工作树不得直接写入中文字符。
- 生产界面、按钮、表格、图表、无障碍名称、错误和安全警告使用英文。
- 源码注释、测试名称、断言和永久夹具使用英文。
- 中文历史用户数据仍须兼容；兼容测试使用 Unicode escape，不把中文字符直接写入源码。
- 不改变 `LedgerData` schema、备份格式、`.lftl` 格式、错误码或业务计算规则。
- 已有中文 Git 历史保留，不进行历史改写。

## Week 日志命名
