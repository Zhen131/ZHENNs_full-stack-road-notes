## 用户最终流程

```text
打开网页版
→ 选择或新建一个版本 2 的 .lftl
→ 解锁
→ 手工录入，或用一句中文描述一笔 / 多笔交易
→ AI 只生成候选草稿
→ 缺失或歧义时逐项追问
→ 页面逐笔显示成交金额、手续费、总支出 / 净到账
→ 用户逐笔确认
→ 网页确定性校验整批候选
→ 全部通过后一次写入当前 .lftl
→ close、readback、解密和完整校验成功后才显示完成
```

Python、Ollama 和 Agent 不接触文件句柄、`.lftl`、IndexedDB、密码、密钥或写入接口。只有现有网页保存链可以发布账本事实。

## 存储与版本 2

### 唯一正式账本

- 用户选择打开哪个 `.lftl`，哪个就是当前账本；应用不扫描、合并或管理其他副本。
- `.lftl` 继续保存完整加密的 current / previous 两代，不保存派生图表和 Agent 状态。
- IndexedDB 只允许保存文件 handle、expected file identity 和连接版本等最小记录。
- 密码与非导出 CryptoKey 只存在当前会话内存。

### 旧格式退役

版本 2 上线后停止支持：

1. 旧版本 1 `.lftl`；
2. 旧版本明文备份；
3. 旧 IndexedDB 完整账本。

遇到旧格式必须清楚提示“不支持，请新建版本 2 账本”，并保持零写入。应用不自动转换、不自动删除旧文件或浏览器记录；用户自行决定是否清理。新版仍保留版本 2 明文备份、零写预检和整本恢复。

### 不变的安全合同

- 加密算法、文件 identity、随机 `revisionId + parentRevisionId` 和 current / previous 两代恢复继续保留。
- 每次保存前复读文件 identity 与 revision；旧页面不得覆盖更新内容。
- `write → close → readback → 解密 → Validator` 全部通过后才显示成功。
- 无法确认磁盘结果时 fail closed：停止当前会话的后续写入，明确告诉用户结果无法确认；不得显示成功，也不得继续盲写。

## 金额、手续费与盈亏

`Trade.totalValue` 固定表示不含手续费的成交金额：

```text
成交金额 = 数量 × 成交均价
买入总支出 = 成交金额 + 实际买入手续费
卖出净到账 = 成交金额 - 实际卖出手续费
已实现净盈亏 = 卖出净到账 - 本次卖出移除的含费成本
未实现净盈亏 = 当前市场价值 - 剩余含费成本
```

固定验收样例：以 6500 USDT 买入 0.1 BTC，手续费 5 USDT，则含费成本为 6505；卖出 0.04 BTC，成交金额 2800、手续费 3，则移除成本 2602、净到账 2797、已实现净盈亏 195、剩余成本 3903。

规则：

- 新账本的内置资产 `quoteCurrency`、新交易、手工 / Binance `PriceSnapshot.currency` 和手续费统一使用 USDT；第一版正式计算不混用其他计价币种。
- 美元只作为近似展示，必须写明 `1 USDT ≈ 1 USD`，不接实时汇率。
- Trade 永久保存用户最终确认的实际 fee；总支出、净到账、成本和盈亏均临时派生，不重复保存。
- 全部卖清时直接移除全部剩余成本，避免十进制分摊残差。
- 历史盈亏只读取每笔 Trade 的实际 fee，不读取后来修改的规则费率。

## 平台与手续费规则

- Trade 新增可选平台；未填写平台仍可手工录入。
- 自动匹配只使用“平台 + 资产”精确匹配，例如 `OKX + BTC`。
- 百分比规则以不含费成交金额为基数，例如 `0.001 = 0.1%`。
- 固定规则直接给出固定金额与手续费币种。
- 修改金额或费率时创建新规则 ID，并停用旧规则；旧规则保留历史引用。
- 无匹配或出现多个有效匹配时不自动猜测，要求用户选择或手填。
- 候选手续费必须在预览中可修改；确认后的 Trade.fee 才是会计事实。

## 本地 AI 与 Agent 边界

### 运行结构

```text
网页文字入口
→ localhost Python 服务
→ 本机 Ollama qwen3:8b
→ 候选草稿 / 追问
→ 网页预览与确定性校验
→ 用户确认后由网页写入 C
```

- 提供一个统一启动入口，检查网页、Python、Ollama 和模型是否就绪。
- 缺少 Ollama、模型或 Python 环境时只给出明确提示，不自动下载安装。
- 第一版模型固定实测 [`qwen3:8b`](https://ollama.com/library/qwen3%3A8b)；官方模型文件约 5.2 GB。本机速度和准确率必须在 03 批实测，不得静默换模型。
- Python 核心同时供网页服务和课程 Notebook 调用，避免维护两套提取逻辑。
- 单 Agent baseline 与双 Agent 使用相同基础模型和公平参数。

### 候选与正式事实

模型首先生成允许缺字段、允许标记歧义的候选对象，不能直接伪造完整 `TradeDraft`。只有补齐问题后才能转换为正式草稿。

以下内容可以进入版本 2 账本：

- 用户确认后的正式 Trade；
- 用户原话及用户亲自给出的必要澄清；
- Trade 实际平台、实际 fee 和可选 feeRuleId。

以下内容永远留在账本外：

- Agent 对话、内部推理、批评和置信度；
- Prompt、原始模型响应、参数和会话状态；
- baseline、多 Agent 指标、实验记录和课程材料；
- 未确认候选及预览状态。

### 追问与写入

- “成交金额 6000，另外手续费 5”可归一为成交金额 6000、手续费 5。
- “总共支出 6000，包含手续费 5”可归一为成交金额 5995、手续费 5。
- “花了 6000，手续费 5”含义不清，必须追问；未说清时零写入。
- 每笔交易都要单独预览和确认。
- 多笔候选全部确认、全部 Validator 通过后才一次写入；任一错误、超时、revision 变化或重复确认均整批零写入。

第一版 AI 只新增文字交易，不编辑或删除历史，不给投资建议，不读取完整账本，不做语音、图片、RAG 或账本问答。

## 已接受的浏览器能力上限

纯网页不能承诺：

- 页面或进程死亡后继续执行 JavaScript 回滚；
- 文件权限永久丢失后仍完成补偿；
- 阻止外部原生程序抢先改写文件；
- 提供操作系统级文件锁或真正单文件事务；
- 标签页关闭后让 Agent 保证后台继续运行。

Week 11 `03B` 是在“任何异常都必须恢复成旧文件”的旧绝对合同下得到的历史 `BLOCKED`；`03C` 在执行前已作废，不生成也不伪造 `03D`。现在采用的是替代旧合同的新边界，不是把旧报告改成 PASS：正常成功必须完整复读；只有能证明磁盘仍是本次精确候选时才补偿；无法确认时停止当前会话后续写入，明确告诉用户结果无法确认，不显示成功，也不继续盲写。这些限制不冒充已修缺陷，未来重新讨论桌面端时再作为设计输入。
