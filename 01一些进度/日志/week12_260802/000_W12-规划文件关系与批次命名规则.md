# Week 12 规划文件关系与批次命名规则

日期：2026-08-09
状态：当前有效
适用范围：`main` 网页账本路线；Week 11 原件冻结不改

## 结论

Week 12 使用 `000 → 00A → 00B → 00C / 00D` 管理长期共识、目标、批次和证据缺口。每个正常批次按一次约 4～5 小时的完整 AI 任务控制范围；开发输入 `NNA` 与独立审查输入 `NNC` 必须在开发前同时生成，只有另一独立任务产出的 `NND = PASS` 才能把 00B 目标标成完成。

计划讨论先讲真实用户流程、再解释技术差别、最后由用户确认。用户听不懂时，应继续把选项讲清楚，不能把抽象术语原样抛给用户，也不能因为解释失败就替用户决定产品取舍。

## 批次文件

`NN` 是两位递增编号，例如 `01`、`02`：

| 文件 | 角色 | 固定输出 |
| --- | --- | --- |
| `NNA` | 开发输入 | 目标、允许修改范围、实现合同、正式测试、完成线 |
| `NNB` | 开发报告 | 实际修改、测试结果、偏差、Git 状态、剩余风险 |
| `NNC` | 独立审查输入 | 冻结候选、审查矩阵、强制证据、PASS / FAIL / BLOCKED 线 |
| `NND` | 独立审查报告 | 逐项目证据、Finding、最终判定、待协调回写项 |

源码执行文件必须同时写明周次和分支，例如：

```text
01A_W12-main-手续费进入成本与净盈亏执行文档.md
01C_W12-main-手续费进入成本与净盈亏独立审查执行文档.md
```

## 固定流程

```text
读取当前源码、测试、Git 和 00A～00D
→ 用户确认本批目标
→ 同时生成 NNA + NNC
→ 开发任务执行 NNA，修改源码并生成 NNB
→ 全新独立任务执行 NNC，源码只读并生成 NND
→ 协调步骤登记 00D、回写 00B 和当前状态
→ 只有 NND = PASS 才进入依赖批次
```

开发任务不能执行本批 NNC；独立审查任务不能修源码、补测试或修改 00B / 00D。自动化全绿、代码合入 `main` 或开发者自评均不能代替 NND。

## 批次大小

每批应满足：

- 一次完整 AI 任务约 4～5 小时可以实现并完成开发侧验证；
- 只包含一个连贯用户结果，可以有多个紧密相关目标；
- 能用固定样例独立验收；
- 不把“顺手做的 UI、重构、迁移或新功能”混入；
- 依赖未满足时不生成 NNA / NNC。

模型能力只能影响执行效率，不能降低批次通过线。Week 12 的 `02` 虽按 GPT-5.6 Sol 高强度任务设计，仍必须保留完整正式测试和独立审查。

## FAIL、BLOCKED 与返工

- `PASS`：全部强制项有足够证据，可以回写 00B。
- `FAIL`：已有证据证明违反强制合同，相关目标和依赖路线暂停。
- `BLOCKED`：没有证明违反，但强制证据不可得；不得猜测为 PASS。
- P0、数据安全类 P1、当前批强制通过项失败，一律阻塞相关路线。
- 普通 P1 / P2 / P3 可以登记 00D 后延期，但必须有最迟处理点。

每批最多立即增加一轮 `NNR1A / NNR1B / NNR1C / NNR1D`。R1 只修本批已确认的阻塞 Finding，不夹带新功能；R1 仍未通过时，保留 00D 并暂停相关路线。

## 防御性测试规则

NNA 负责把本批风险写成仓库内永久测试；NNC 只读复跑。涉及文件、密码、保存、导入、清空、并发或 AI 写入时，按适用范围覆盖：

- 写入、关闭、复读、验证任一步失败不得显示成功；
- 文件身份、revision、会话代次变化后，旧异步结果不得覆盖新状态；
- 取消、锁定、卸载、超时或权限变化后不得继续写；
- 损坏、未知版本、边界大小和非法候选必须 fail closed；
- 多笔 AI 交易任一失败时整批零写入；
- 测试对象只限用户拥有的本地仓库、虚构数据和受控环境。

独立审查发现正式测试缺口时，把缺口写入 NND；不能在审查任务里临时写测试再自证通过。

## Git 边界

- 00 层、批次文档和当前状态属于工作区根文档仓库 `main`。
- 产品源码属于 `01一些进度/产出/LocalFirstTradingLedger/` 的独立源码仓库 `main`。
- 两边分别检查 branch、status 和 diff，不混合提交。
- 未经用户授权不提交、不推送、不合并、不删除分支。
- `CS2026` 保持暂停；不得自动复制、合并或同步 `main` 改动。

## 自检表

| 问题 | 通过线 |
| --- | --- |
| 用户能否看懂本批结果 | 先写一条真实使用流程，再写内部术语 |
| A/C 是否同时生成 | 开发开始前，两份输入已冻结同一目标和通过线 |
| 批次是否过大 | 不含第二个独立用户结果或无关重构 |
| 完成状态是否可信 | 只有 NND PASS 才勾选 00B |
| BLOCKED 是否被绕过 | 只允许无依赖路线继续，相关依赖保持暂停 |
| 两个 Git 仓库是否混淆 | 状态、diff、提交和推送分别报告 |
