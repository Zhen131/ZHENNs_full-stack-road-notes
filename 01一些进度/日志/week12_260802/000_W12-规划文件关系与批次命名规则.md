# Week 12 规划文件关系与批次命名规则

日期：2026-08-09；流程更新：2026-08-10
状态：当前有效
适用范围：`main` 网页账本路线；Week 11 原件冻结不改

## 结论

Week 12 使用 `000 → 00A → 00B → 00C / 00D` 管理长期共识、目标、批次和证据缺口。自 2026-08-10 起，默认交付单元改为 `NNA → NNB`：开发任务必须完成永久正式测试、适用的真实浏览器检查和开发报告，用户可在核对风险后授权合入 `main`。`NNC / NND` 不再要求每个功能批次立即执行，而是在若干相关功能完成后、重要发布前或真实数据风险需要重新确认时集中执行。

开发完成、代码合入与独立复验是三个不同状态。00B 可以据 `NNB = PASS` 标记“开发完成并合入”，但必须同时注明独立复验是 PASS、待集中复验、FAIL 或 BLOCKED，不能把延期写成独立 PASS。

计划讨论先讲真实用户流程、再解释技术差别、最后由用户确认。用户听不懂时，应继续把选项讲清楚，不能把抽象术语原样抛给用户，也不能因为解释失败就替用户决定产品取舍。

## 批次文件

`NN` 是两位递增编号，例如 `01`、`02`：

| 文件 | 角色 | 固定输出 |
| --- | --- | --- |
| `NNA` | 开发输入 | 目标、允许修改范围、实现合同、正式测试、完成线 |
| `NNB` | 开发报告 | 实际修改、测试结果、偏差、Git 状态、剩余风险 |
| `NNC` | 可延期的独立审查输入 | 一个或多个已合入批次的冻结范围、审查矩阵与 PASS / FAIL / BLOCKED 线 |
| `NND` | 集中独立审查报告 | 逐项目证据、Finding、独立判定和待协调回写项 |

源码执行文件必须同时写明周次和分支，例如：

```text
01A_W12-main-手续费进入成本与净盈亏执行文档.md
01C_W12-main-手续费进入成本与净盈亏独立审查执行文档.md
```

## 固定流程

```text
读取当前源码、测试、Git 和 00A～00D
→ 用户确认本批目标
→ 生成并执行 NNA，修改源码、补永久测试并生成 NNB
→ NNB = PASS 后由用户决定是否合入、推送和进入下一开发批次
→ 协调步骤回写 00B、00D、当前状态和日志
→ 若干相关功能完成、重要发布或风险 Gate 到达时，再生成或更新集中 NNC
→ 全新独立任务只读审查最新 main 并生成 NND
```

开发任务不能把自己的 NNB 写成独立 PASS；独立审查任务不能边修源码边自证通过。自动化全绿、代码合入 `main` 或开发者自评不能代替 NND，但独立 NND 延期也不再自动阻塞后续无直接依赖的开发批次。

## 批次大小

每批应满足：

- 一次完整 AI 任务约 4～5 小时可以实现并完成开发侧验证；
- 只包含一个连贯用户结果，可以有多个紧密相关目标；
- 能用固定样例完成开发侧验证，并可被后续集中独立审查复用；
- 不把“顺手做的 UI、重构、迁移或新功能”混入；
- 依赖未满足时不生成 NNA；NNC 只在集中审查节点生成或更新。

模型能力只能影响执行效率，不能降低开发通过线。每个 NNA 仍必须保留永久测试和适用真实流程；集中独立审查减少重复执行次数，不删除安全测试，也不允许开发任务跳过强制失败场景。

## 开发判定、独立判定与返工

- `NNB PASS`：开发范围、永久测试、质量门和适用真实流程已经完成，可以标记“开发完成”；是否合入和推送仍由用户授权。
- `NND PASS`：全新独立任务已对集中范围取得足够证据，可以标记“独立复验通过”。
- `FAIL`：已有证据证明违反强制合同，相关目标和直接依赖路线暂停。
- `BLOCKED`：没有证明违反，但本次要求的证据不可得；不得猜测为 PASS，可在 00D 登记后等待集中复验。
- P0、数据安全类 P1、当前批强制通过项失败，一律阻塞相关路线。
- 普通 P1 / P2 / P3 可以登记 00D 后延期，但必须有最迟处理点。

开发阶段发现代码缺陷时可以增加一轮 `NNR1A / NNR1B`；集中独立审查发现阻塞 Finding 时，再决定是否创建对应 R1 开发与独立复验。R1 只修已确认 Finding，不夹带新功能。

## 防御性测试规则

NNA 负责把本批风险写成仓库内永久测试并完成开发侧真实流程；集中 NNC 只读复跑并补充独立证据。涉及文件、密码、保存、导入、清空、并发或 AI 写入时，按适用范围覆盖：

- 写入、关闭、复读、验证任一步失败不得显示成功；
- 文件身份、revision、会话代次变化后，旧异步结果不得覆盖新状态；
- 取消、锁定、卸载、超时或权限变化后不得继续写；
- 损坏、未知版本、边界大小和非法候选必须 fail closed；
- 多笔 AI 交易任一失败时整批零写入；
- 测试对象只限用户拥有的本地仓库、虚构数据和受控环境。

独立审查发现正式测试缺口时，把缺口写入 NND；不能在审查任务里临时写测试再自证通过。

## Git 边界

- 00 层、批次文档和当前状态属于工作区根文档仓库 `main`。
- 产品源码属于 `01一些进度/产出/LocalFirstTradingLedger/` 的独立源码仓库 `main`。
- 两边分别检查 branch、status 和 diff，不混合提交。
- 未经用户授权不提交、不推送、不合并、不删除分支。
- `CS2026` 保持暂停；不得自动复制、合并或同步 `main` 改动。

## 自检表

| 问题 | 通过线 |
| --- | --- |
| 用户能否看懂本批结果 | 先写一条真实使用流程，再写内部术语 |
| A/B 是否闭合 | NNA 的实现、永久测试、真实流程与 NNB 报告一致 |
| 批次是否过大 | 不含第二个独立用户结果或无关重构 |
| 完成状态是否可信 | 00B 分开写开发完成与独立复验状态 |
| 独立审查是否被取消 | 只能集中延期，不能把未执行写成 PASS |
| 两个 Git 仓库是否混淆 | 状态、diff、提交和推送分别报告 |
